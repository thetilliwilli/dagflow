# Варианты архитектуры вычислителя (2026-10-10)

Контекст: DAG по данным без циклов; engine sans-IO с внешним планировщиком; одинаковые
результаты в Local, Worker и Server; нужны асинхронные ноды, сигнальные порты, задержки по
времени, циклы по сигналам. Текущий вычислитель заменяется целиком.

## Варианты только для данных (первый раунд)

| Вариант | Данные | Async | Сигналы | Детерминизм | Сложность | Вердикт |
|---|---|---|---|---|---|---|
| 1. Топологический батч с пометкой грязных (прежний evaluator) | да | нет | нет | полный | средняя | база, заменяется |
| 2. Батч + отсечение по равенству | да | нет | нет | полный | низкая надстройка | идея сохраняется в новом ядре |
| 3. Батч + поколения и состояние ожидания | да | да | нет | полный при «ждать всех» | средняя | поколения сохраняются |
| 4. Батч для данных + очередь FIFO для сигналов | да | да | да | полный внутри тика | средняя-высокая | предшественник выбранного |
| 5. Push-pull (dirty + lazy, как signals) | да | плохо | нет | полный | высокая | выбран для data-слоя в виде pull с мемо |
| 6. Инкрементальные вычисления с динамическими зависимостями | да | да | нет | полный | очень высокая | не нужен |
| 7. Чистый push (observer) | с глитчами | плохо | да | нет | низкая | отклонён |
| 8. Полный пересчёт на каждом такте (Lustre) | да | нет | нет | полный | низкая | эталон для тестов (оракул) |
| 9. Акторы, потоковая обработка | да | да | да | нет | высокая | не нужен |

## Варианты с временем, событиями и циклами (второй раунд)

| | Данные без глитчей | Async | Задержки | Циклы по сигналам | Детерминизм | Расстояние от кода |
|---|---|---|---|---|---|---|
| A. Два слоя, один планировщик: ленивые данные + очередь событий с временем | да | да | да | да, с защитой | да, при виртуальном времени | ядро переписать, модель графа расширить |
| B. Событийная симуляция с дельта-циклами (VHDL, SystemC) | в конце точки времени | да | да | через задержку | да | переписать ядро |
| C. Синхронно-реактивные языки (Esterel, Lustre, Céu) | да | через такты | да | только через задержку | полный | нужен анализ причинности |
| D. Токенный dataflow, сети Кана (LabVIEW) | плохо | да | ломает теорему Кана | через начальный токен | да для untimed | большое |
| E. Поток исполнения + данные по требованию (Unreal) | через pull | да | да | да | да | сводится к A |
| F. Акторы с очередью (Node-RED, Max) | нет | да | да | да | слабый | потеря свойств |

**Выбран A** с заимствованиями: анализ причинности из C (отказ в кольце без задержки при
создании связи), виртуальный планировщик из F (тесты с временем мгновенны), ленивые
данные из E и TouchDesigner. **B в запасе**, если два слоя окажутся неестественными:
однороднее, но теряет ленивость и даёт повторные пересчёты внутри мгновения. Вариант 8
первого раунда используется в лабе как эталонный интерпретатор.

## Общее для любого варианта

- Виртуальное время: engine получает `now` в `tick(now)`, возвращает «следующее
  пробуждение в T».
- Поколения для асинхронных ответов; отмена через адаптер.
- Защита кольца без задержки: лимит переходов за тик плюс запрет на уровне редактора.
- Состояние с историей не выводится из графа: при переподключении теряется (явно в spec).
- «Одновременно»: данные, изменённые в одном тике, видны сигналам единым снимком; два
  сигнала в одном тике доставляются по очереди.
