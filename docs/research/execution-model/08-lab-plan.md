# План лабы движка (2026-10-10)

Лаба это spike: отдельная ветка `lab/execution-model`, папка `lab/` в корне как приватный
workspace-пакет, исключённый из `npm run typecheck`, `lint` и `npm test`. В master не
вливается. Итог лабы: семантика, подтверждённая сценариями; каноническая модель нода и
SDK v1, замороженные после двух спокойных итераций; тексты для `/speckit-specify`. Код
лабы остаётся на ветке и теге, в master уходят только заметки этой папки.

## Как пользоваться планом

- Шаги идут строго по порядку. Каждый шаг заканчивается зелёным `npm run lab:test`,
  обновлённым `lab/PROGRESS.md` и коммитом на ветке лабы.
- Команда пользователя на шаг одна и та же: **«Выполни шаг N плана лабы»**. Перед работой
  Claude читает этот файл и `lab/PROGRESS.md`, выполняет шаг, обновляет PROGRESS.md,
  коммитит и пишет в чат три вещи: что сделано, что посмотреть, что дальше.
- Если шаг упирается в вопрос о поведении, Claude останавливается и задаёт вопрос. Ответ
  записывается строкой с датой в `00-decisions.md` (на ветке лабы, в master попадёт при
  заморозке) и в `lab/SEMANTICS.md`.
- Если в сессии потерян контекст, та же команда, этот план и PROGRESS.md его
  восстанавливают.
- Отклонения от плана допустимы и записываются в PROGRESS.md; план остаётся эталоном и
  правится только по договорённости.
- Worktree не нужен: работа идёт в этой же папке на ветке лабы. Если понадобится
  параллельно делать фичу на master, тогда `git worktree add ../dagflow-lab lab/execution-model`.

## Структура лабы (целевая)

```
lab/
  package.json          @dagflow/lab, private; скрипты test, typecheck
  tsconfig.json         ядро по правилам engine (lib ESNext, types []); стенд и тесты с node/vitest
  vitest.config.ts      свой конфиг, проект «lab»
  README.md             как запускать, как добавить сценарий и нод
  SEMANTICS.md          правила семантики (рабочая копия 06-proposed-model.md, источник истины лабы)
  PROGRESS.md           что сделано по шагам, отклонения, отложенное
  fixtures/
    data/*.json         сценарии только с данными (паритет с сегодняшним движком)
    signals/*.json      сигналы, время, циклы
    composite/*.json    составные ноды
    latent/*.json       эффекты, поколения, отмена
  src/
    model/              типы: граф v2, NodeTypeDef v2, события, запросы эффектов, TickResult, NodeState v2
    reference/          эталонный интерпретатор: простейшая реализация семантики
    engine/             кандидат: pull с мемоизацией + очередь событий
    harness/            runScenario, сравнение трасс, виртуальные часы, поддельные fetch/fs/random
    nodes/              lab-ноды для сценариев (Start, Button, Delay, NextTick, Counter, Hold, Changes, Collect, Fetch, ReadFile, Random, Timer)
    sdk/
      v1/ sdk.ts, adapter.ts, nodes/*.ts, nodes.test.ts, NOTES.md
      v2/ …
      active.ts         какая версия подключена к стенду
  test/
    fixtures.test.ts    все сценарии через эталон и кандидат; трассы равны
    generative.test.ts  случайные графы и правки: кандидат = эталон
```

## Формат сценария

```jsonc
{
  "name": "diamond-signal",
  "composites": [],
  "graph": { "nodes": [...], "edges": [...] },        // граф v2: порты с kind
  "steps": [
    { "at": 0, "set":    { "node": "a", "port": "value", "value": 3 } },
    { "at": 0, "signal": { "node": "btn", "port": "press" } },
    { "at": 0, "expectEvents": [ { "node": "log", "port": "in", "payload": 3 } ] },
    { "at": 0, "expectEffects": [ { "node": "f", "port": "go", "generation": 1 } ] },
    { "at": 0, "effect": { "node": "f", "generation": 1, "ok": { "body": "hi", "status": 200 } } },
    { "at": 1000, "expect": { "sum": { "status": "ok", "outputs": { "result": 6 } } } },
    { "at": 1000, "expectWake": null }
  ]
}
```

Стенд группирует шаги по `at`, применяет `set`, `signal`, `effect`, зовёт `tick(at)`,
затем проверяет `expect*`. Трасса (состояния, события, эффекты, пробуждения по тикам)
снимается целиком и сравнивается между эталоном и кандидатом.
