# Предлагаемая модель исполнения, v0 (2026-10-10)

Рабочая гипотеза для лабы, не spec. Правила уточняются сценариями лабы (`lab/SEMANTICS.md`
становится рабочей копией этого документа), итог переносится в spec фичи.

## 1. Граф

- Нод: тип, имя экземпляра, позиция, ручные значения data-входов (как сейчас).
- Порт: имя, вид (`data` или `signal`), тип значения (number, text, boolean, array,
  object, any; у сигнала ещё `none`, то есть без payload), у data-входов `required` и
  `default`.
- Связь: data → data или signal → signal, типы совместимы по нынешним правилам.
  Смешивать виды нельзя.
- Граф данных без циклов. Граф сигналов может содержать циклы, если в каждом цикле есть
  нод с `defers`.

## 2. Виды нодов

| Вид | Порты | Код | Состояние | Когда работает |
|---|---|---|---|---|
| pure | только data | `compute(inputs) → outputs`, чистая синхронная | нет | когда его выход запросили (pull); результат мемоизируется до изменения входов |
| exec | хотя бы один signal-вход; data и signal в любом сочетании | `on[port](ctx)`, синхронный | да, `init()` | на каждое событие в signal-вход |
| latent | как exec | `run[port](ctx) → Promise`, исполняет адаптер | да | на событие; завершение приходит позже событием |

Правила:

- Выходной data-порт exec- и latent-нода хранит последнее зафиксированное значение. Пока
  нод не срабатывал, значения нет: потребитель `waiting` с сообщением о том, что источник
  ещё не срабатывал.
- `defers: true` у типа означает: всё, что нод испускает вниз, попадает в более поздний
  момент (Delay, Next tick, любой latent). Такие ноды разрывают циклы.
- Чистота pure-нода это контракт: `env` ему не передаётся, `needs` у него пустой.

## 3. Данные: pull с мемоизацией

- `value(node, port)` вычисляет pure-нод по требованию. Приоритет входа: связь → ручное
  значение → умолчание порта. Статусы как сейчас: ok, waiting, blocked, error.
- Мемо инвалидируется при изменении подписи нода (тип, ручные значения, входящие связи)
  и при коммите выходов exec-нода выше по данным.
- Glitch-free по построению: при вычислении D оба пути к A видят одно и то же A.
- Политика «кого тянуть» снаружи ядра. Умолчание редактора: после каждого тика тянуть все
  ноды открытых документов, это паритет с сегодняшним поведением. Ленивость это
  оптимизация, не семантика, потому что эффекты только в exec и latent.

## 4. Сигналы: очередь событий на виртуальном времени

- Событие: `{ rootId, time, seq, target: { node, port }, payload? }`.
- Очередь упорядочена по `(time, seq)`. Внешние события (клик по сигнальному входу в окне
  свойств, Start при открытии документа, завершение эффекта) получают новый `rootId` и
  время текущего тика.
- `tick(now)`: применить накопленные правки и внешние события; доставлять события с
  `time ≤ now` по порядку; каждое срабатывание может породить новые события в тот же
  момент (хвост текущего мгновения) или в будущее. Результат: изменённые состояния,
  список доставленных событий (для подсветки в интерфейсе), запросы эффектов, время
  следующего пробуждения или «нет».
- Срабатывание exec-нода: обработчик получает снимок data-входов (pull в этот момент),
  payload, `state`, `out`. Выполняется до конца. Затем атомарный коммит: data-выходы
  записаны и мемо потомков инвалидировано; испущенные сигналы поставлены в очередь с
  текущим временем и возрастающим `seq`; `out.after(port, ms, payload?)` ставит событие в
  `now + ms`. Потребитель сигнала, читающий data-выходы источника, видит уже
  зафиксированные значения. Это закрывает вопрос «что раньше: выход или событие».
- Разветвление: сигнал на выходе с N связями порождает N событий в порядке связей в
  графе, все с тем же `rootId`. Срабатывание по каждому пути.
- Кольцо без задержки: лимит событий за тик (например 10 000) переводит нод в `error`
  «Signal loop without delay». Редактор дополнительно отказывает в связи, замыкающей
  сигнальный цикл без нода с `defers`, по аналогии с сегодняшним отказом в цикле.
- Next tick: событие кладётся в отдельную очередь, которая вливается в основную в начале
  следующего `tick`.

## 5. Latent-ноды, эффекты, поколения

- На событие latent-нод не исполняется в движке. Движок увеличивает поколение экземпляра
  и добавляет в результат тика запрос эффекта `{ node, port, generation, inputs,
  payload }`. Предыдущий запрос того же экземпляра считается отменённым: адаптер
  получает `cancel` и прерывает его через AbortSignal.
- Адаптер исполняет `run[port]({ inputs, payload, env, signal })` и зовёт
  `completeEffect(node, generation, outcome)`. Движок на следующем тике превращает
  завершение в событие: коммит data-выходов и сигналов из результата; статус `ok` или
  `error`. Устаревшее поколение отбрасывается молча.
- Пока запрос в полёте: статус `running`; потомки по данным `waiting`.
- `env` даёт только возможности из `needs` типа. Если у хоста их нет, нод в `error`
  «Requires: fs (not available in this target)», в палитре пометка. Список возможностей
  хост сообщает в welcome (протокол v2).
- Таймеры не через `env`: `out.after` и нод Delay живут в очереди движка. Так виртуальное
  время остаётся единственными часами, и conformance-тесты с задержками мгновенны.

## 6. Состояние и история

- `state` экземпляра живёт в памяти хоста. Не сохраняется в файл, не передаётся при
  переподключении. После `open` сигнальный слой стартует с нуля, exec-выходы пусты.
- Детерминизм: data-слой это функция графа; сигнальный слой это функция графа и
  последовательности внешних событий с их временами. Conformance-тесты на виртуальных
  часах с записанной последовательностью обязаны совпасть в Local, Worker и Server.

## 7. Составные ноды

Flatten как сейчас: внутренние ноды с id `экземпляр/нод`, у каждого своё состояние. Ноды
Input и Output составного нода получают сигнальные порты. Проверка циклов на развёрнутом
графе.

## 8. API движка (sans-IO)

```ts
interface Engine {
  setGraph(graph: Graph, library: CompositeDef[]): void;
  setValue(nodeId: string, port: string, value: JsonValue): void;
  /** Внешнее событие; время ему присвоит ближайший tick. */
  signal(nodeId: string, port: string, payload?: JsonValue): void;
  completeEffect(nodeId: string, generation: number, outcome: EffectOutcome): void;
  tick(now: number): TickResult; // { states, events, effects, nextWake }
  state(nodeId: string): NodeState;
}
```

Адаптер: вызывает `tick(now)` при любом входящем сообщении и по таймеру на `nextWake`;
исполняет `effects` с `env` своей среды; результаты возвращает через `completeEffect`.

## 9. Пробелы и умолчания, найденные при независимом разборе

- **Идентичность события при разветвлении.** Vuo ждёт все части и исполняет нод один
  раз, Unreal исполняет по путям. Принято: по путям, `rootId` хранится, Join возможен
  позже нодом, не правилом движка.
- **Payload у сигналов.** Без него потоки теряют данные при двух событиях за тик
  (data-выход перезаписан). Принято: необязательный payload.
- **Политика pull.** UX-риск статуса «не запрашивался». Принято: тянуть всё по умолчанию.
- **Асинхронные data-ноды.** Отложены, не запрещены навсегда: Rete.js тянет данные
  асинхронно, нужны лишь поколения.
- **Не разобрано:** составные ноды с сигналами в деталях, undo при живых таймерах,
  несколько вкладок в одном хосте, протокол v2. Это материал лабы и specify.

## 10. Запасной вариант

Однородная событийная симуляция с дельта-циклами (VHDL): данные как связи с нулевой
задержкой. Проще по числу понятий, но теряет ленивость и даёт повторные пересчёты внутри
мгновения. Переход к нему рассматривается после вехи M2 лабы, если два слоя окажутся
неестественными.
