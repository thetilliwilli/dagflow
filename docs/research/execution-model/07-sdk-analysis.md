# SDK нодов: разбор предложения и направление (2026-10-10)

## Что предлагала сессия об SDK (2026-10-09)

1. Три слоя: SDK vN (форма записи, меняется каждую итерацию) → адаптер vN → каноническая
   модель нода (фиксируется один раз) → движок. Разработчик библиотеки видит только SDK.
2. Каноническая модель «максимально общая», в push-стиле: экземпляр с `input(name, value,
   kind)`, `emit` в любой момент, состояние, динамические порты, объявленные возможности.
3. Платформа меняется один раз под каноническую модель: асинхронный flush, `emit` вне
   тика, состояние экземпляра, тип порта pulse, `dispose`.
4. Место: ветка `lab/node-sdk`, worktree, папка `lab/` в корне как workspace-пакет,
   исключённый из продуктовых проверок; версии SDK в `lab/sdk/v1`, `v2`, …; headless-стенд
   с поддельными часами, fetch и fs; флаг сборки, подмешивающий библиотеку в редактор;
   журнал в `docs/research/node-sdk/`.
5. Набросок SDK v1: `node('add', { inputs: { a: t.number() }, outputs, compute })` и
   `node('timer', { needs: ['timers'], inputs: { start: t.pulse() }, state, on: { start({
   input, state, out, env }) } })`.
6. Формат файла нода: JSDoc-шапка (что делает, что проверить, на что обратить внимание),
   затем код на воображаемом SDK.

## Что сохраняется

- Три слоя и адаптер на версию SDK: правильный инструмент для итераций эргономики.
  ComfyUI и Node-RED годами держат контракт нода стабильным, меняя рантайм под ним.
- Версии SDK рядом, без удаления до финала.
- Headless-стенд с виртуальным временем и поддельными эффектами; он же место для
  сценариев нового движка.
- Папка в репозитории, исключённая из `typecheck`, `lint` и `npm test`. Хост протокола
  уже принимает внешний реестр через опцию `registry`.
- Формат файла нода с JSDoc-шапкой.
- Журнал решений в `docs/research/` (эта папка, не отдельная `node-sdk/`).

## Что меняется после сессии о моделях вычисления

| Положение | Что показала сессия о моделях | Следствие |
|---|---|---|
| Платформа расширяется один раз | Вычислитель переписывается целиком, ядро другое | Список одноразовых работ устарел. Лаба сначала про движок, потом про SDK |
| Каноническая модель это push, `input(name, value, kind)` и `emit` | Данные и сигналы отличаются семью свойствами; движку нужно знать, чистый ли нод, чтобы мемоизировать, тянуть и отсекать по равенности | Каноническая модель общая по информации, а не по выразительности: вид нода, вид порта, чистота, `needs`, `defers`. Иначе гарантии теряются ниже слоя адаптера и SDK их не вернёт |
| `compute` и `on` сосуществуют на одном ноде | Чистота это контракт типа | Нод либо pure, либо exec/latent. Одного типа с обоими не бывает |
| `env.timers.every(ms, cb)` в коде нода | Время двигает только движок | Таймеры через `out.after` и нод Delay в очереди движка; в `env` таймеров нет |
| Ноды в редакторе с первой итерации | Сигнальные порты, статусы, каталог от цели требуют правок UI и протокола | Не в лабе. Редактор получает новый движок через фичу |
| Вопрос «пульсы плюс значения или чистые сигналы» без ответа | Два вида портов, переходники Hold и Changes | Закрыт |
| Pulse это событие без значения | Потоки теряют данные без payload | Сигнал с необязательным payload |

## Каноническая модель нода (контракт движка, набросок)

```ts
interface NodeTypeDef {
  id: string; title: string; category: string; description: string;
  kind: 'pure' | 'exec' | 'latent';
  inputs: PortDef[]; outputs: PortDef[];      // PortDef.kind: 'data' | 'signal'
  needs?: Capability[];                       // 'fetch' | 'fs' | 'random' | …; только exec/latent
  defers?: boolean;                           // всё испущенное попадает в более поздний момент
  compute?: (inputs: Inputs) => Outputs;      // pure
  init?: () => State;                         // exec, latent
  on?: Record<string, (ctx: HandlerContext) => void>;              // exec: по сигнальному входу
  run?: Record<string, (ctx: EffectContext) => Promise<Outcome>>;  // latent: исполняет адаптер
}
```

Это контракт между SDK (любой формы) и движком. Он публикуется позже, чем SDK, и может
стать публичным, когда понадобятся сторонние стили записи (как декларативный стиль n8n).

## Направление SDK v1 (поправленный набросок)

```ts
import { node, t } from '@dagflow/sdk';

export const add = node('add', {
  title: 'Add', category: 'Math',
  inputs: { a: t.number(), b: t.number() },
  outputs: { result: t.number() },
  compute: ({ a, b }) => ({ result: a + b }),          // kind: pure выводится из compute
});

export const timer = node('timer', {
  title: 'Timer', category: 'Time', defers: true,
  inputs: { interval: t.number(1), times: t.number(-1), start: t.signal(), stop: t.signal() },
  outputs: { tick: t.signal(), count: t.number() },
  state: () => ({ count: 0, armed: false }),
  on: {
    start({ input, state, out }) { state.count = 0; state.armed = true; out.after('tick', input.interval * 1000); },
    stop({ state }) { state.armed = false; },
    tick({ input, state, out }) {                        // внутренний сигнал самому себе
      if (!state.armed) return;
      out.count(++state.count);
      if (input.times === -1 || state.count < input.times) out.after('tick', input.interval * 1000);
    },
  },
});

export const fetchText = node('fetch', {
  title: 'Fetch', category: 'Network', needs: ['fetch'],
  inputs: { url: t.text(), go: t.signal() },
  outputs: { body: t.text(), status: t.number(), done: t.signal(), failed: t.signal(t.text()) },
  run: {
    async go({ input, env, signal }) {
      const r = await env.fetch(input.url, { signal });
      return { body: await r.text(), status: r.status, done: true };
    },
  },
});
```

Критерии эргономики для разбора каждой итерации: объём кода на типичный нод; type safety
(входы и выходы выводятся из объявлений, `out.count(…)` типобезопасен); явность вида нода
без флагов; невозможность неправильного использования (pure не получает `env`, таймер не
получает `setTimeout`); читаемость без метапрограммирования; одинаковая запись для
браузера и сервера.

## Чего не делать в лабе

Эти возможности из списка целей ортогональны модели исполнения и идут отдельными фичами
после лабы:

- интеграция в редактор (палитра «Lab», флаг сборки, инструкции «как посмотреть»);
- динамические порты из кода нода и из редактора (как в Rivet `getInputDefinitions`);
- нод из любой JS-функции в рантайме (`Math.max`);
- скрипт-нод с произвольным кодом в редакторе;
- несериализуемые значения между нодами (стримы, функции, буферы).

Причины: модель исполнения нестабильна, и каждая из них тянет UI, протокол или формат
файла. Скрипт-нод и нод из функции означают исполнение пользовательского кода на хосте,
то есть упираются в BACKLOG «Защита сервера выполнения». Несериализуемые значения
меняют протокол: значения живут на хосте, редактор видит проекции.
