# Модель вычисления графа: журнал решений

Обсуждение замены вычислителя (`packages/engine/src/evaluator.ts`) на модель, которая
умеет порты данных и сигнальные порты, асинхронные ноды, задержки по времени и циклы
по сигнальным связям. Здесь — цель, принятые решения и открытые вопросы; разбор
вариантов — в соседних заметках.

**Итог**: фича ещё не начата. Когда начнётся — здесь появится ссылка на `specs/NNN-…/`,
и папка будет заморожена.

## Цель (со слов пользователя, 2026-10-10)

- Текущий вычислитель — первый набросок, он заменяется целиком, совместимость с ним
  не нужна.
- Нужны:
  - порты данных (значение) и сигнальные порты (событие, «прямой вызов»);
  - асинхронные ноды, например запрос по HTTP;
  - ноды, испускающие сигнал с задержкой, например таймаут 3 с;
  - циклы в графе по сигнальным связям (по связям данных цикл бессмысленен и остаётся
    запрещён).
- Требование фичи 001 «всё реактивно, отдельного запуска нет» (FR-013…FR-016) было
  решением той фичи и наследовать его обязательным не нужно: кто и когда
  вычисляется — решается заново.

## Решения 2026-10-10

| Вопрос | Решение |
|---|---|
| Чистый push (observer) | Отклонён: glitches на ромбах, экспонента пересчётов на цепочках ромбов, порядок зависит от порядка подписки, с асинхронностью недетерминирован. См. [01](01-push-pull-diamond.md). |
| Единый тип порта «сигнал с флагом сохранять» | Отклонён как модель для пользователя: кроме «сохранять» различаются ещё пять независимых свойств, осмысленных наборов два — данные и сигналы. Как механизм внутри движка допустим. См. [02](02-data-vs-signals.md). |
| Рекомендуемая модель | Событийное ядро на виртуальном времени для сигналов + данные по требованию (pull с пометкой «устарел» и кэшем). Три вида нодов: чистый, исполняемый, латентный. См. [05](05-proposed-model.md). |
| Асинхронные ноды данных | Не вводить: асинхронность и эффекты живут только в исполняемых нодах, слой данных синхронный и чистый. |
| Запасной вариант | Однородная событийная симуляция с дельта-циклами (данные как связи с нулевой задержкой). Без ленивости. См. [04](04-variants.md). |

## Открытые вопросы (к `/speckit-specify` и `/speckit-clarify`)

1. **Кого вычислять.** Политика pull: только то, что запросил сигнал; выделенный нод в
   окне свойств; ноды-стоки после каждого тика; всё. Настройка, свойство типа нода или
   фиксированное правило.
2. **Кольцо без задержки.** Лимит переходов за мгновение с ошибкой нода или запрет на
   этапе редактирования (в каждом сигнальном цикле обязан быть латентный нод).
3. **Несколько сигналов в один нод.** Каждое событие — отдельное срабатывание; ожидание
   нескольких — явный нод (Join / Gate).
4. **Правка графа во время полёта.** Что делать с латентными нодами при удалении нода,
   удалении связи, изменении входов.
5. **Состояние выполнения вне файла.** Очередь событий, кэши и таймеры не сохраняются и
   не передаются при переподключении хоста; после переподключения сигнальная часть
   начинается заново.
6. **Выходы данных у исполняемого нода.** «Последний результат»; что видит потребитель
   до первого срабатывания.
7. **Старт.** Что порождает первое событие: нод Start при открытии документа, кнопка,
   внешнее сообщение.
8. **Детерминизм и conformance.** Данные — функция графа; сигналы — функция графа и
   последовательности внешних событий с временами. Тесты на виртуальных часах.

## Связи

- `specs/BACKLOG.md`, «Защита сервера выполнения»: обязательна до фичи, дающей нодам
  на сервере эффекты (`fetch`). HTTP-нод из этой темы — ровно такая фича: защита
  сервера должна быть реализована раньше или в той же очереди.
- Конституция: sans-IO ядра сохраняется — движок не читает часы и не ставит таймеры,
  время приходит в `tick(now)`, движок возвращает момент следующего пробуждения.

## Термины (кандидаты в глоссарий при старте фичи)

- **Data port** (порт данных) — порт со значением-снимком; потребитель читает его
  в любой момент; связи данных без циклов.
- **Signal port** (сигнальный порт, exec-порт) — порт, через который проходит событие;
  события доставляются по очереди, связи могут образовывать циклы.
- **Event** (событие) — запись в очереди движка: адресат, полезная нагрузка, метка
  (виртуальное время, порядковый номер).
- **Pure node** (чистый нод) — только порты данных, синхронная функция без эффектов,
  вычисляется по требованию.
- **Exec node** (исполняемый нод) — срабатывает по входному сигналу, читает входы
  данных как снимок, делает работу, испускает сигналы.
- **Latent node** (латентный нод) — исполняемый нод, завершающий работу в будущем
  (таймер, HTTP).
- **Virtual time** (виртуальное время) — время, которое движку сообщает адаптер;
  движок сам часы не читает.
