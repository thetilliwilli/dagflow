# Модель исполнения графа: журнал решений

Обсуждение замены вычислителя (`packages/engine/src/evaluator.ts`) на модель, которая
умеет порты данных и сигнальные порты, асинхронные ноды, задержки по времени и циклы по
сигнальным связям, а также SDK для авторов библиотек нодов. Здесь цель, принятые решения
и открытые вопросы; разбор в соседних заметках, план работ в [08-lab-plan.md](08-lab-plan.md).

**Итог**: фича не начата. Сначала лаба движка на ветке `lab/execution-model` по плану 08.
Когда лаба заморожена и стартует фича, здесь появится ссылка на `specs/NNN-…/`, и папка
будет заморожена.

## Цель (со слов пользователя, 2026-10-09 и 2026-10-10)

- Текущий вычислитель это первый набросок; он заменяется целиком, совместимость с ним
  не нужна.
- Нужны: порты данных и сигнальные порты («прямой вызов», событие); асинхронные ноды
  (запрос по HTTP); ноды, испускающие сигнал с задержкой (таймаут 3 с); циклы в графе по
  сигнальным связям (по связям данных цикл бессмысленен и остаётся запрещён).
- Требование фичи 001 «всё реактивно, отдельного запуска нет» (FR-013…FR-016) было
  решением той фичи; наследовать его обязательным не нужно, кто и когда вычисляется
  решается заново.
- Параллельная цель: SDK на TypeScript для сторонних библиотек нодов (npm-пакеты) и
  место, где форму записи нодов можно итерировать без многочасового рефакторинга
  платформы под каждую версию. См. [07-sdk-analysis.md](07-sdk-analysis.md).

## Источники

- Сессия об SDK нодов (2026-10-09): организация лабы, трёхслойная схема SDK → адаптер →
  каноническая модель → движок, набросок SDK v1, шесть вопросов без ответа.
- Сессия о моделях вычисления (2026-10-10): push/pull/батч, проблема ромба, данные и

- Независимый разбор обеих сессий с проверкой по коду проекта и внешним источникам
  (2026-10-10): заметки 04, 06, 07, 08.

## Решения 2026-10-10

| Вопрос | Решение |
|---|---|
| Чистый push (observer, как Node-RED и Max) | Отклонён: glitches на ромбах, экспонента пересчётов на цепочках ромбов, порядок зависит от порядка подписки, с асинхронностью недетерминирован. [01] |
| «Все порты сигнальные с флагом сохранять» | Отклонено как модель пользователя: один бит не несёт семь независимых свойств (триггер, слияние, отсечение по равенству, повтор при подписке, чистота, история). Допустимо как механизм внутри движка. [02] |
| Виды портов | Два: данные и сигналы. Переход между мирами явными нодами: Hold (сигнал → данные), Changes (данные → сигнал). [02, 06] |
| Виды нодов | pure (только данные, чистая синхронная функция), exec (есть сигнальный вход, синхронный обработчик, состояние), latent (exec с завершением позже: HTTP, файл). [06] |
| Данные | Pull с мемоизацией, glitch-free по построению. Политика «кого тянуть» снаружи ядра; умолчание редактора: тянуть всё, как сейчас. [06] |
| Сигналы | Очередь событий с меткой (виртуальное время, порядок). Доставка строго по метке. Кольцо это цепочка событий, не рекурсия. [06] |
| Время | Только виртуальное: движок получает `now` в `tick(now)` и возвращает время следующего пробуждения. `Date.now` и таймеры в движке запрещены, как и сейчас. [06] |
| Циклы | По данным запрещены. По сигналам разрешены, если в каждом цикле есть нод с задержкой (`defers`). Проверка при создании связи; в рантайме лимит событий за тик. [06] |
| Асинхронность | Только в latent-нодах. Движок выдаёт адаптеру запрос эффекта с номером поколения; устаревшие ответы отбрасываются. Асинхронных data-нодов в первой версии нет. [06] |
| Эффекты и возможности | Код нода получает `env` с возможностями (fetch, fs, random…), объявленными типом нода (`needs`). Движок остаётся sans-IO: вызов latent-нода исполняет адаптер. [06, 07] |
| Payload у сигналов | Сигнал несёт необязательное значение. Выходы данных и сигналы exec-нода фиксируются атомарно после обработчика; сигналы доставляются после коммита. [06] |
| Идентичность события | У каждого события корневой id внешнего события. Срабатывание по каждому пути (как в Unreal); слияние «один раз на событие» (как в Vuo) возможно позже нодом Join благодаря id. [06] |
| Состояние с историей | Состояние exec-нодов, очередь и таймеры не сохраняются в файл и не передаются при переподключении; сигнальный слой стартует заново. [06] |
| Горячие и холодные входы | Нет. Data-вход никогда не триггер; триггер только сигнал. [02, 04] |
| Каноническая модель нода | Общая по информации, а не по выразительности: хранит вид нода, вид порта, чистоту, `needs`, `defers`. Push-модель «любой вход это сообщение» отклонена как каноническая. [07] |
| Как двигаться | Лаба движка (spike) до `/speckit-specify`: семантика, сценарные фикстуры, эталонный интерпретатор, кандидат движка, затем каноническая модель и SDK v1. [08] |
| Чего не делать в лабе | Интеграция в редактор, динамические порты, нод из любой JS-функции, скрипт-нод в редакторе, несериализуемые значения. Отдельные фичи после лабы. [07] |

## Открытые вопросы (решаются в лабе или на specify)

1. Политика pull в редакторе, если понадобится ленивость: статус «не запрашивался» или
   тянуть всё всегда.
2. Два сигнала в один exec-нод за один тик: срабатывает дважды (принято). Нужен ли
   встроенный Join и его семантика (по `rootId` или по счётчику).
3. Правка графа «в полёте»: отменять ли latent-нод при удалении нода, при правке его
   входов, при удалении связи к нему.
4. Составные ноды с сигнальными портами, состояние внутренних экземпляров.
5. Что запускает первое событие: нод Start при открытии документа, кнопка в окне свойств,
   внешнее сообщение.
6. Протокол v2: сообщения о доставленных событиях, запросах эффектов, пробуждении,
   возможностях хоста.
7. Undo/redo при живых таймерах и состоянии.

## Связи

- BACKLOG «Защита сервера выполнения»: обязательна до эффектов на сервере. Latent-ноды
  на сервере это именно такая фича; она идёт в одной очереди с моделью исполнения.
- BACKLOG «Каталог нодов от цели»: нужен вместе с библиотеками нодов и возможностями
  хоста (палитра показывает, что умеет цель).
- Конституция: принцип I (простота) и V (прозрачность). Лаба это исследование, не
  продукт: её код не вливается в master, в master уходят только заметки этой папки.
