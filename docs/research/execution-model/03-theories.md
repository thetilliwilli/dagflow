# FRP, discrete event systems, transducers (2026-10-10)

Не одно и то же, но одна область: причинные преобразования входного потока во времени в
выходной. Разница в том, что каждая теория считает главным объектом.

**FRP (Functional Reactive Programming).** Взгляд из теории языков: какова денотация
реактивной программы. Эллиотт и Худак (1997): Behavior = функция `Time → a` на
непрерывном времени, Event = множество пар `(Time, a)`. Программа это выражение из
комбинаторов (`lift`, `hold`, `snapshot`, `switch`), чистое, без понятия «шаг». Glitches
в классическом FRP нет по определению: значение берётся в точке времени, а не
распространяется. Практические потомки (Elm старых версий, signals в Solid и Vue, Yampa)
дискретны и упрощены.

**Discrete event systems (DES).** Взгляд из теории управления и имитационного
моделирования. Система меняет состояние только в моменты событий. Формализмы: автоматы,
Petri-сети, супервизорное управление Рамаджа и Вонэма, DEVS Зейглера (состояние, функция
продвижения времени `ta(s)`, внутренний переход, внешний переход по входу, функция
выхода). Вопросы: достижимость, тупики, одновременные события, расписание симуляции. Любой
симулятор с очередью событий по времени это DES.

**Transducers.** В теории автоматов: конечный преобразователь (Мили, Мура), причинная
функция «список входов → список выходов» с конечным состоянием; времени нет, есть
порядок. В Clojure: составная трансформация шага свёртки, отделённая от источника и
приёмника; stateful transducers вроде `take` это машины Мили.

| | FRP | DES | Transducers |
|---|---|---|---|
| Главный объект | значение как функция времени | состояние и события системы | преобразователь последовательности |
| Время | непрерывное в теории, есть «сейчас» | дискретные моменты, интервалы важны | нет, только порядок |
| Состояние | скрыто в комбинаторах | явное, центральное | явное, локальное |
| Одновременность | нет по построению | ключевая проблема, решается явно | не возникает |
| Чего хотят | композиционная семантика | анализ и симуляция | переиспользуемые куски конвейера |

Общая почва: причинные функции на потоках, формально коалгебры или машины Мили. Рядом
стоят синхронные языки (Lustre, Esterel), сети процессов Кана и акторы.

## Перевод на проект

- Прежний engine это синхронный dataflow в духе Lustre без состояния: нод это функция.
- Сигнальные порты и ноды вроде счётчика это машины Мили, то есть transducers.
- Асинхронный HTTP-нод с ожиданием и отменой устаревших ответов это атомарная
  DEVS-модель: состояние «жду», внешний переход по приходу ответа, внутренний по таймауту.
- Вопрос «данные или сигналы» это вопрос FRP: Behavior или Event; ответ FRP такой же:
  два типа и явные переходники `hold` и `changes`.
- Очередь событий на виртуальном времени с меткой (время, порядок) это ядро DES;
  виртуальный планировщик для тестов это Rx `TestScheduler`.
