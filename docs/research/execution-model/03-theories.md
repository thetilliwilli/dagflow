# FRP, discrete event systems, transducers (2026-10-10)

Три теории об одной области — причинные преобразования входного потока во времени в
выходной — с разных сторон.

**FRP (Functional Reactive Programming).** Взгляд из теории языков: какова денотация
реактивной программы. Эллиотт и Худак (1997): Behavior = `Time → a` на непрерывном
времени, Event = множество пар `(Time, a)`. Программа — выражение из комбинаторов
(`lift`, `hold`, `snapshot`, `switch`), чистое, без шага. Glitches отсутствуют по
определению: значение берётся в точке времени, а не распространяется. Практические
потомки (Elm старых версий, signals в Solid/Vue, Yampa) дискретны и упрощены.

**Discrete event systems (DES).** Взгляд из теории управления и имитационного
моделирования. Состояние меняется только в моменты событий, между ними постоянно.
Формализмы: автоматы, Petri-сети, супервизорное управление Рамаджа–Вонэма, DEVS
Зейглера (состояние, функция продвижения времени `ta(s)`, внутренний переход, внешний
переход по входу, функция выхода). Вопросы: достижимость, тупики, одновременные события,
расписание симуляции. Любой симулятор с очередью событий по времени — DES.

**Transducers.** Два близких значения. В теории автоматов — конечный преобразователь
(машина Мили/Мура): причинная функция `список входов → список выходов` с конечным
состоянием; времени нет, только порядок. В Clojure — составная трансформация шага
свёртки, независимая от источника и приёмника; stateful transducers (`take`,
`partition`) — те же машины Мили.

| | FRP | DES | Transducers |
|---|---|---|---|
| Главный объект | значение как функция времени | состояние и события системы | преобразователь последовательности |
| Время | непрерывное (в теории), есть «сейчас» | дискретные моменты, интервалы важны | нет, только порядок |
| Состояние | скрыто в комбинаторах | явное, центральное | явное, локальное |
| Одновременность | нет по построению | ключевая проблема | не возникает |
| Чего хотят | композиционная семантика | анализ и симуляция | переиспользуемые куски конвейера |

Общая почва: причинные функции на потоках (коалгебры, машины Мили). Разница не в
выразительности, а в том, о чём каждая теория заставляет думать. Рядом — синхронные
языки (Lustre, Esterel), сети процессов Кана, акторы.

Перевод на проект: вычислитель данных — синхронный dataflow без состояния (нод = машина
Мура без памяти = функция); сигнальные ноды со состоянием (счётчик) — машины Мили;
асинхронный нод с ожиданием и отменой устаревших ответов — атомарная DEVS-модель; выбор
«данные или сигналы» — вопрос FRP (Behavior или Event), и ответ FRP тот же: два типа и
явные переходники `hold` и `changes`.
