# Удалённый engine: журнал решений

Обсуждение архитектуры выполнения workflow на сервере. Здесь фиксируются принятые
решения; черновики и рисерчи — в соседних файлах.

**Итог**: фича 004 — [specs/004-engine-targets/](../../../specs/004-engine-targets/)
(specify 2026-10-07). Папка заморожена: источник истины — артефакты фичи.

## Цель (со слов пользователя)

- Кроссплатформенный пакет engine: один и тот же код работает в браузере и на
  бекенде (Node / Bun / Deno).
- Редактор подключается к engine по выбору пользователя:
  1. локально — в том же фрейме браузера (как сейчас);
  2. в соседнем WebWorker;
  3. удалённо — по URL сервера (например, `localhost:8080`).
- Engine во всех вариантах один и тот же.
- Нужно спроектировать:
  - протокол клиент ↔ engine (формат сообщений, транспорт);
  - как UI общается с клиентской прослойкой и привязывается к данным внутри нодов.

## Решения 2026-10-06 (до поправки конституции)

| Вопрос | Решение |
|---|---|
| Где хранятся workflow при удалённом engine | Только у клиента (браузер / рабочая папка). Сервер получает граф для выполнения и держит состояние только в памяти, своего хранилища у него нет. |
| Аутентификация | Нет. Сервер рассчитан на доверенную сеть и по умолчанию слушает только localhost. Многопользовательского режима нет. |
| Серверные среды | Node, Bun, Deno — все три проверяются тестами. Engine — чистый ECMAScript без API конкретной среды. |
| Оформление | Монорепо на npm workspaces: `packages/engine`, `packages/protocol`, `packages/server`, приложение — отдельный пакет. |

## Что меняется в конституции (1.1.0 → 2.0.0)

- Принцип III «Только локальные данные» переопределён (MAJOR): данные по-прежнему
  только у пользователя, но приложению разрешено подключаться к engine, на который
  пользователь явно указал (свой сервер). Сторонние облачные сервисы по-прежнему
  запрещены.
- «Ограничения»: продукт — веб-приложение плюс необязательный сервер выполнения.
  Engine кроссплатформенный. Пункт «серверную часть не проектировать заранее» снят.
- Аутентификация и многопользовательский режим по-прежнему вне рамок; сервер по
  умолчанию слушает только localhost.

## Решения 2026-10-07 (архитектура, раунд 1)

| Вопрос | Решение |
|---|---|
| Режим «в том же фрейме» | Тоже через протокол, по in-memory каналу: один путь кода для всех режимов. |
| Транспорт сервера | WebSocket. Node — зависимость `ws` (8.22.x, peer-зависимости опциональны), Bun/Deno — встроенный WS. |
| Граф по протоколу | Целиком на каждое изменение структуры + быстрый `setValue`. Патчи — только если покажут замеры. |
| Подписки на внутренние ноды составных (`watch`) | Не сейчас. |
| Bun и Deno для тестов | devDependency: npm-пакеты `bun` (1.4.x) и `deno` (2.9.x). |
| Цель переносимости | Сейчас Node/Bun/Deno, но ядро проектируется как встраиваемое в любой JS-рантайм (njs, Office Add-ins, AWS Lambda, QuickJS и т. п.). См. 02-portability.md. |
| Конституция 2.1.0 | Свежий TS/ESNext + сборка под среду; sans-IO ядра и хоста; эффекты через возможности хоста; проверка собранного бандла. Коммит 8a691a3. |

## Решения 2026-10-07 (ошибки, переподключение, доступ к серверу)

| Вопрос | Решение |
|---|---|
| Ошибки и переподключение | Как в 05-errors-reconnect.md: снимки вместо очереди, паузы 0,5→10 с, ноды приглушены с последними значениями, редактирование не блокируется. |
| Доступ к серверу с других Origin | **Осознанно открыт полностью.** WebSocket-рукопожатие принимается с любым `Origin`. Любой HTTP-ответ сервера, включая preflight `OPTIONS`, несёт разрешающие заголовки: `Access-Control-Allow-Origin: *`, `-Methods: *`, `-Headers: *`, `-Private-Network: true` (Chrome Private Network / Local Network Access). Защита — позже, отдельным механизмом (BACKLOG). |

## Решения 2026-10-07 (выбор цели в интерфейсе)

| Вопрос | Решение |
|---|---|
| Цель по умолчанию | «In this tab» (как сейчас). |
| Индикатор в верхней панели | Виден всегда. |
| Адрес сервера | Короткий адрес (`localhost:8080`, `domain.com`); схему `ws`/`wss` подбирает подключатор, успех = `welcome`. |
| Список целей | Один плоский список: индикатор выбранной + адрес + тип (Local / Worker / Server). Локальные строки постоянные, серверов до 5 последних, «×» — убрать. Поле + «Connect» добавляет сервер. |
| Порт | Только тот, что указал пользователь; подключатор порт не додумывает. |
| Хранение настройки | IndexedDB через `idb-keyval`, ключ `dagflow:engine` (как настройка хранилища). |
| Параметр `?engine=` в URL | Не нужен. |
| Ручная смена цели | Пробное подключение; переключение только после `welcome`, при неудаче — ошибка у поля и прежняя цель. |

## Решения 2026-10-07 (plan 004)

| Вопрос | Решение |
|---|---|
| Место редактора в монорепо | Корень остаётся пакетом редактора; packages/engine, protocol, server. Пакеты отдают TS-исходники. |
| Хост/клиент | sans-IO, строки на входе; Local — in-memory канал строк. |
| Сборка сервера | Vite SSR → один dagflow-server.mjs; запуск из проекта = сборка + запуск. |
| Conformance | Vitest-проект запускает бандл в node/bun/deno и сравнивает с хостом в процессе. |
| Типы Bun/Deno | Свой runtimes.d.ts вместо @types/bun и типов Deno. |
| LNA | Таймаут открытия сокета не применяется, пока разрешение в состоянии prompt. |
| Safari + https + ws://localhost | Ограничение браузера, в Assumptions spec. |
| Лимит 8 МБ | На сообщение: граф вкладки и отдельно library. |
| Bun и Deno в тестах (пересмотр) | Не devDependencies: Node, Bun, Deno пользователь ставит сам; `engines` в packages/server; conformance падает с понятным сообщением, если среды нет в PATH. peerDependencies отклонены (npm 7+ сам ставит обязательные peer). |
| Safari | Убран из поддерживаемых и из всех артефактов проекта. Поддержка — Chromium и Firefox. |
