# Ошибки и переподключение (черновик, 2026-10-07)

## Ключевая идея: синхронизация снимками, а не очередью операций

- Граф — у клиента (источник истины). Хост хранит только производную копию.
- Поэтому клиенту **не нужна очередь** неотправленных изменений: пока связи нет,
  правки просто копятся в сторе (и автосохраняются, как сейчас). После подключения
  клиент шлёт **текущий снимок**: `hello` → `library` → `open` для каждой открытой
  вкладки. Всё, что было «пропущено», покрывается снимком.
- Состояние хоста привязано к соединению → после переподключения хост всегда
  «чистый», расхождений быть не может.

## Состояния подключения (срез стора `engine`)

```ts
type EngineTarget =
  | { kind: 'inline' }
  | { kind: 'worker' }
  | { kind: 'remote'; url: string };      // ws://localhost:8080

type EngineStatus =
  | { kind: 'connecting' }                                  // первая попытка / смена цели
  | { kind: 'ready' }
  | { kind: 'offline'; attempt: number; retryAt: number }   // связь потеряна или не установлена
  | { kind: 'incompatible'; host: string }                  // версии не совпали — без автоповтора
  | { kind: 'failed' };                                     // worker падает раз за разом
```

```
            смена цели / старт
                  │
                  ▼
┌──────────► connecting ──welcome──► ready
│                │  │                  │
│  version-      │  │ нет связи        │ обрыв
│  mismatch      ▼  ▼                  ▼
│          incompatible   offline ◄────┘
│                         │   ▲
│                 таймер /│   │ неудача
│        «Retry now»      ▼   │
└──────────────────── connecting
```

## Повторные попытки

- Пауза растёт: 0,5 → 1 → 2 → 4 → 8 → 10 с (потолок), со случайным разбросом ±20 %,
  чтобы несколько вкладок браузера не стучались одновременно.
- Попытки бесконечные, пока вкладка открыта; кнопка «Retry now» сбрасывает паузу.
- Сброс счётчика — после успешного `welcome`.
- Ожидание `welcome`: если за 5 с после открытия сокета ответа нет — попытка
  считается неудачной (сокет есть, а хост «не тот» или завис).
- Кроме таймера, попытка сразу при событии браузера `online`.

## Что видит пользователь

### Индикатор подключения
- Всегда виден в правом конце панели вкладок: точка-статус + короткий текст.
  Для `inline` в состоянии `ready` — скромно («Local engine»), чтобы не шуметь.
- По щелчку открывается левая панель на разделе «Engine» (рядом с «Storage»): выбор
  цели и адрес сервера.

```
[ Workflow 1 ] [ Sum ]                                    ● Remote · localhost:8080
[ Workflow 1 ] [ Sum ]                    ◌ Offline — retrying in 4 s  [Retry now]
[ Workflow 1 ] [ Sum ]   ⚠ Engine version differs (server 0.3.0, editor 0.2.0) [Use local]
```

### Ноды, пока связи нет
- Показывают **последние известные значения**, приглушённо, с подписью в окне
  «Properties»: «Last known value — engine offline».
- Редактирование не блокируется: добавлять ноды, связывать, править значения можно
  (проверки идут локальной копией engine). Новые и изменённые ноды — статус
  `computing` до подключения.
- После подключения полный снимок `states` заменяет приглушённые значения.

### Ошибки протокола → реакция клиента

| Код | Пользователю | Клиент делает |
|---|---|---|
| `version-mismatch` | баннер: версии разные, что обновить; кнопка «Use local engine» | статус `incompatible`, без автоповтора |
| `invalid-message` | уведомление «Engine rejected a request. Results may be outdated.» | деталь — в консоль; повторно `open` документа один раз |
| `unknown-doc` | ничего | повторно `open` (самовосстановление) |
| `too-large` | у вкладки: «This workflow is too large for the remote engine (limit: 8 MB).» | ноды вкладки приглушены; новая попытка при следующей правке |
| `internal` | уведомление «Engine failed to process the workflow. Retrying.» | повторно `open` документа |

Ошибки самих нодов — как сейчас: в `NodeState` рядом с нодом.

### Особенности режимов
- **inline**: обрыва не бывает. Исключение из хоста ловит адаптер → `internal`.
- **worker**: событие `error` у Worker → перезапуск worker + уведомление «Engine
  restarted after a failure». Три падения за минуту → статус `failed`, предложение
  перейти на локальный engine.
- **remote**: всё, что выше.

### Смена цели
- Пользователь выбирает цель в разделе «Engine» → старое соединение закрывается,
  `connecting`, ноды приглушены до снимка.
- Цель хранится в `localStorage` — это настройка браузера, а не данные workflow
  (принцип III; в файлы workflow не попадает).
- При старте приложение подключается к сохранённой цели. Если удалённый сервер
  недоступен — редактор всё равно полностью работает; в индикаторе `offline` +
  «Use local engine».
- Адрес проверяется при вводе: только `ws://` / `wss://`, иначе — ошибка у поля.

## Сервер

- Обрыв соединения → документы соединения освобождаются.
- Сообщения CLI понятные (принцип IV): «Port 8080 is already in use. Start with
  --port &lt;number&gt;.» — без трассировок.
- `--host 0.0.0.0` → предупреждение: «The engine has no authentication. Anyone on
  your network can run workflows on it.»
- **Доступ открыт для любого Origin (решение 2026-10-07).** WebSocket-рукопожатие
  без проверки `Origin`; любой HTTP-ответ, включая preflight `OPTIONS` (204), — с
  `Access-Control-Allow-Origin: *`, `Access-Control-Allow-Methods: *`,
  `Access-Control-Allow-Headers: *`, `Access-Control-Allow-Private-Network: true`.
  Защита — отдельной фичей (specs/BACKLOG.md, «Защита сервера выполнения»).
- Пинг `ws`-кадрами каждые 30 с; нет ответа → соединение закрыто.

## Ограничения браузера (учесть в research)

- Страница по `https://` не может открыть `ws://` на не-localhost адрес (mixed
  content) — нужен `wss://`. `ws://localhost` браузеры считают безопасным.
- Chrome вводит запрос разрешения на обращение публичных сайтов к локальной сети
  (Local Network Access). Для dev-сервера на localhost не мешает; важно, если редактор
  будет опубликован в интернете.

## Тесты (принцип II)

- Хост: каждая ветка ошибок — unit-тест на `receive()` без сокетов (sans-IO).
- Клиент: машина состояний подключения — unit-тесты с фейковым каналом и фейковыми
  часами (паузы, сброс, `incompatible`, повторный `open` после `unknown-doc`).
- e2e: запуск сервера на свободном порту → подключение → остановка сервера →
  индикатор offline, приглушённые ноды, правка → запуск сервера → значения
  пересчитаны.

## Разбор: чем опасен чужой сайт, открывающий ws://localhost (2026-10-07)

- Браузер не применяет к WebSocket политику same-origin/CORS: скрипт с любого сайта
  может открыть `ws://localhost:8080`. Браузер лишь добавляет заголовок `Origin`, и
  проверять его — задача сервера.
- **Сейчас риск практически нулевой**: ноды чистые (ни файлов, ни сети), документы
  изолированы по соединению — чужой сайт не видит workflow пользователя, может только
  считать свои графы на его CPU (нагрузка).
- **Станет уязвимостью**, если сервер получит:
  1. возможности с эффектами (`fetch`, файлы) — чужой сайт использует сервер как
     прокси в локальную сеть / к файлам пользователя (SSRF), обходя защиту браузера;
  2. общее состояние между соединениями (сохранённые документы, многопользовательский
     режим) — чтение и подмена чужих данных.
- Проверка Origin защищает только от сайтов в браузере; программа вне браузера
  подделает заголовок — от неё защищает только аутентификация / закрытый порт.
- Решение: см. 00-decisions.md.
