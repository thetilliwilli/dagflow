# Встраиваемость engine в любой JS-рантайм (2026-10-07)

## Цель

Сейчас: Node, Bun, Deno (+ браузер: фрейм и WebWorker). В перспективе: nginx njs,
Office Add-ins (Excel JS), AWS Lambda, QuickJS и другие встраиваемые JS-движки.
Node/Bun/Deno — первая апробация кроссплатформенности.

## Что значит «синхронный engine»

- `compute(inputs) → outputs` — обычная функция: возвращает результат сразу, без
  `Promise`/`await`, без ввода-вывода.
- `evaluator.flush()` пересчитывает все грязные ноды за один вызов и возвращает
  новые состояния. Внутри нет таймеров, событий, сети.
- Это свойство — главный козырь переносимости: синхронный чистый код работает в любом
  рантайме, где есть ECMAScript, даже без event loop.

## Принцип: ядро без ввода-вывода (sans-IO)

Слои, от самого переносимого к самому зависимому от среды:

| Слой | Пакет | Что может использовать |
|---|---|---|
| Ядро: модель графа + вычислитель | `@dagflow/engine` | только ECMAScript (язык + стандартная библиотека: Map, Set, JSON, Math…) |
| Хост протокола | `@dagflow/protocol` | то же, что ядро. Принимает сообщение → отдаёт сообщения через переданный `send`. Ни таймеров, ни сокетов. Планирование `flush` — инъекция (`schedule`) от адаптера. |
| Адаптер среды | `@dagflow/server` (node/bun/deno), worker, inline | API конкретной среды: WebSocket, postMessage, setTimeout/queueMicrotask, CLI-аргументы |

Чтобы встроить engine в новую среду, достаточно написать адаптер (десятки строк):
получить сообщения → `host.receive(msg)`; `send` → отправить средствами среды.
В средах без постоянного соединения (Lambda, Excel custom function) можно звать ядро
напрямую без протокола: `setGraph` → `flush` → результат.

## Запрещено в ядре и хосте (проверять линтером/tsconfig)

- `lib: ["ES20xx"]` без DOM, `types: []` — уже так в `tsconfig.engine.json`.
- Глобалы среды: `setTimeout`, `queueMicrotask`, `console`, `crypto`, `structuredClone`,
  `TextEncoder`, `performance`, `process`, `Deno`, `Bun`, `fetch`.
- Источники недетерминизма: `Date.now`, `Math.random` — через инъекцию, если понадобятся.
- Зависимости npm — ноль (Valibot для схем протокола — вопрос: допустить в protocol
  или проверку сообщений писать руками? Решить в plan).

## Уровень языка: пишем на свежем, сборка подстраивается под среду (решение 2026-10-07)

- Исходники — последний TypeScript / ESNext (модули, новые API стандартной
  библиотеки). Не ограничиваем язык пересечением возможностей рантаймов.
- Под каждую среду — отдельная сборка (target + полифилы + формат бандла): ESM для
  Node/Bun/Deno/браузера, один файл без импортов для встраиваемых сред, при
  необходимости даунлевел синтаксиса и core-js-полифилы стандартной библиотеки.
  Инфраструктура сборок появится по мере появления сред; в первой фиче — только ESM.
- Проверка: тестируется **собранный бандл** в целевой среде, а не исходники.
- Три класса «возможностей» — разная природа, разное решение:
  1. **Синтаксис** (`?.`, классы, `using`, деструктуризация) — транспилятор понижает. ✅
  2. **Стандартная библиотека ECMAScript** (`Object.hasOwn`, `toSorted`, Set-методы,
     Iterator helpers) — полифилы (core-js) по потребности. ✅
  3. **Неполифилимое**: `Proxy`, lookbehind и некоторые флаги RegExp, `WeakRef`/
     `FinalizationRegistry`, `SharedArrayBuffer`/`Atomics`, BigInt в средах без него.
     Короткий стоп-лист для ядра (линтер) — или среда без них просто не
     поддерживается. ⚠️
  4. **API среды выполнения** (`setTimeout`, `console`, `fetch`, `crypto`,
     `structuredClone`, `process`) — это не ECMAScript, никакая сборка их не создаст
     (в рантайме без event loop нет таймеров). Поэтому — запрет в ядре + инъекция. ❌
- Факт (проверено): njs с 0.9.1 умеет движок QuickJS (`js_engine qjs;`, ES2023), а
  старый собственный движок njs (ES5.1 + часть ES6) объявлен устаревшим с 1.0.0.
  Даже njs не требует писать старый код.

## Как проверяем

- Один набор conformance-тестов ядра и протокола (без Vitest-специфики, на
  `node:test`-совместимом или самописном раннере?) запускается в Node, Bun, Deno.
  Вопрос для plan: Vitest в Bun/Deno работает не идеально; варианты — `bun test`,
  `deno test` с общими файлами тестов или собственный минимальный раннер.
- Будущие среды (QuickJS через `quickjs-emscripten`, njs) — тем же набором.
