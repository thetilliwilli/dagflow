# Зачем сверять версии engine (2026-10-07, clarify 004)

## Почему расхождение вообще возможно

Редактор держит свою копию engine для правил графа (палитра, порты, canConnect), хост
вычисляет своей. Для Local и Worker копии из одной сборки — расхождения не бывает.
Расхождение возможно только с сервером: это отдельный процесс, который живёт своей
жизнью.

Самый реальный сценарий — разработка: правим код engine → Vite мгновенно обновляет
редактор (HMR) → процесс сервера в памяти со старым кодом. Или `git pull`/смена ветки
без перезапуска сервера. Номер semver в этих случаях не меняется.

## От чего защищаемся

| # | Сценарий | Что видит пользователь без проверки | Вред |
|---|---|---|---|
| 1 | Формат сообщений протокола изменился | ошибки обмена или неверно понятые сообщения | высокий, но громкий |
| 2 | В редакторе новый нод, сервер его не знает | нод в ошибке «Unknown node type» | средний, видно |
| 3 | Порт нода переименован/изменён | редактор разрешает связь, сервер её не видит → «waiting»/blocked | средний, запутывает |
| 4 | Изменилось вычисление нода (исправили ошибку, округление) | **другое число**, без всяких признаков | **высокий, тихий** |
| 5 | Изменился текст ошибки нода | другой текст | косметика |

Сервер новее редактора — те же случаи 1, 3, 4, 5 (2 не мешает: редактор не шлёт
незнакомые ноды).

Главный риск — №4: тихо неверный результат, которому пользователь доверяет.
Его не ловит ни semver (не поднимают), ни отпечаток каталога (порты те же).
Ловит только отпечаток исходников engine.

## Варианты политики

- Только версия протокола: защищает от 1; 2–5 остаются.
- Протокол + отпечаток исходников, отказ: защищает от всего; в разработке
  напоминает перезапустить сервер.
- Протокол + отпечаток исходников, предупреждение: подключение разрешено, но
  индикатор и ноды помечены «results may differ».

## Идея пользователя: редактор = только UI, engine скачивается с сервера

### Что решает
- Сценарии 2, 3, 5: палитра, порты и тексты — из того же кода, что считает.
- Сценарий 1 — только если клиент протокола тоже скачивается; тогда граница
  переезжает на API «UI ↔ скачанный engine» (форма NodeState, функции canConnect,
  linkCandidates…) — её тоже придётся версионировать. Проблема переносится, не исчезает.

### Новые проблемы
1. **Выполнение чужого кода в странице редактора.** Сервер — любой адрес, без
   аутентификации, возможно без шифрования (подмена в сети). Скачанный код получает
   всё: IndexedDB, OPFS, дескриптор рабочей папки (чтение и запись файлов
   пользователя), все workflow. Сейчас сервер присылает только JSON, проверенный
   схемами. Изоляция (sandbox iframe / worker) делает вызовы асинхронными — а правила
   графа нужны синхронно на каждый жест.
2. **Смена цели = смена «языка».** При переключении цели engine в работающем
   редакторе подменяется: другая палитра, другие правила; открытые вкладки, история
   отмены, сохранённые workflow проверены прежним.
3. **Без связи.** Сервер недоступен при старте — каким engine редактировать? Нужна
   встроенная или закэшированная копия → в редакторе снова свой engine.
4. **Local и Worker** всё равно требуют встроенного engine → «только UI» не получается.
5. Сервер становится раздатчиком статических файлов (HTTP), появляется вопрос сборки
   engine под браузер на стороне сервера.

## Уточнение к сценарию 4 (исправление прежнего вывода)

В режиме Server значения считает только сервер; локальное вычисление редактора не
используется. Поэтому «другое число» — это не рассогласование внутри сеанса, а просто
«сервер другой версии программы» (как старая версия приложения). Это видно по версии
в индикаторе. Реальное рассогласование — только там, где локальные правила редактора
встречаются с сервером: сценарии 1, 2, 3.

## Альтернатива без скачивания кода: каталог нодов от хоста как данные

- В `welcome` хост присылает описания своих нодов (id, название, категория, порты) —
  данные, а не код. Палитра и проверки связей берут каталог текущей цели.
  Функции правил графа уже работают от `NodeRegistry` (данные), `compute` для них не
  нужен.
- Решает 2 и 3 без выполнения чужого кода; 1 — версия протокола (в неё входят и
  правила совместимости типов портов).
- Готовит почву для будущих серверных нодов с возможностями (файлы, сеть): их палитра
  придёт с сервера.
- Цена: палитра меняется при смене цели; кэш каталога для работы без связи; нод
  неизвестного цели типа → существующая ошибка «Unknown node type».
