# Глоссарий

Термины проекта с одним закреплённым значением. Формат записи:
`Term (термин по-русски, близкие термины и имена в коде) - описание`, где Term — главное
название на английском. Правила ведения — в `CLAUDE.md`, раздел «Документация».

## Граф

- **Node** (нод) - элемент графа: ссылка на тип нода, имя экземпляра, позиция на холсте
  и значения входов, заданные вручную.
- **Node type** (тип нода, `NodeTypeDef`) - описание операции: название, категория, порты
  и правило вычисления выходов по входам. Бывает встроенным и составным.
- **Instance** (экземпляр, имя экземпляра) - нод как представитель своего типа в конкретном
  графе. У составного нода определение одно, а экземпляров много; правка определения
  пересчитывает все экземпляры. Имя экземпляра — имя нода в графе, по умолчанию равно
  названию типа.
- **Composite node** (составной нод, определение составного нода, `CompositeDef`) - тип
  нода, заданный внутренним графом; получается сворачиванием группы нодов. Его порты
  задают ноды «Input» и «Output» внутреннего графа. Определение хранится в библиотеке,
  экземпляры — в workflow.
- **Port** (порт, `PortDef`) - вход или выход нода с именем и типом (число, текст,
  логическое, массив, объект, любое). Значение порта — JSON-значение.
- **Link** (связь, edge, `Edge`) - направленное соединение выходного порта одного нода с
  входным портом другого; допустима только при совместимых типах портов.
- **Workflow** (workflow, граф, `Workflow`) - граф из нодов и связей без циклов, с
  идентификатором и именем; единица сохранения, выгрузки, загрузки и открытия во вкладке.
- **Library** (библиотека составных нодов, библиотека, сообщение `library`) - все
  определения составных нодов хранилища; общая для всех workflow, показывается в палитре;
  целям вычисления передаётся отдельно от графов.

## Редактор

- **Tab** (вкладка, документ, `doc`) - открытый в редакторе workflow со своей позицией и
  масштабом холста и историей отмены. Для цели вычисления вкладка — документ.
- **Canvas** (холст) - рабочая область с нодами и связями; занимает весь экран, остальные
  окна плавают поверх него.
- **Palette** (палитра) - полоса с типами нодов по категориям внизу холста; открывается
  Пробелом, нод добавляется перетаскиванием или щелчком.
- **Properties** (окно свойств, property grid) - плавающее окно выделенного нода: порты,
  их значения и состояние. Значения портов правятся только здесь; связи создаются
  перетаскиванием строки порта на другой нод.
- **Working folder** (рабочая папка, рабочее хранилище) - папка на диске, выбранная
  пользователем; в неё автоматически сохраняются workflow и библиотека. Без папки —
  хранилище браузера (OPFS).

## Вычисление

- **Engine** (engine, вычислитель, `@dagflow/engine`) - модель графа и реактивный
  вычислитель; один пакет для браузера, Node, Bun и Deno, без API среды (sans-IO).
- **Engine target** (цель вычисления, Local / Worker / Server) - где считается workflow:
  Local (то же окно), Worker (фоновый поток браузера), Server (сервер выполнения по
  адресу). Выбирается в разделе «Engine» левой панели, хранится в браузере, не в workflow.
- **Host** (хост протокола, хост, `@dagflow/protocol`) - сторона цели: держит в памяти
  копии открытых вкладок, пересчитывает и отправляет состояния нодов. Один и тот же код
  в окне, в Worker и на сервере.
- **Client** (клиент протокола, клиент, `@dagflow/protocol`) - сторона редактора:
  отправляет хосту библиотеку и графы открытых вкладок, принимает состояния и
  единственный пишет их в стор.
- **Adapter** (адаптер среды, адаптер, shim) - тонкий слой между хостом или клиентом и
  вводом-выводом конкретной среды: канал в памяти для Local, `postMessage` для Worker,
  WebSocket для Node, Bun и Deno. Планирует пересчёт хоста своим таймером.

## Модель исполнения (исследование)

Термины из `docs/research/execution-model/`; закрепляются и уточняются фичей, которая
заменит вычислитель.

- **Data port** (порт данных) - порт с текущим значением, которое можно прочитать в
  любой момент; связь data → data. Все сегодняшние порты такие.
- **Signal port** (сигнальный порт, exec pin, event) - порт, по которому проходят
  события; значения «сейчас» у него нет; связь signal → signal; событие может нести
  необязательное значение (payload).
- **Event** (событие) - одно прохождение сигнала: цель, виртуальное время, порядок,
  корневой id внешнего события, payload. Живёт в очереди движка.
- **Pure node** (чистый нод) - нод только с портами данных и чистой синхронной функцией;
  считается по требованию, результат мемоизируется до изменения входов.
- **Exec node** (исполняемый нод) - нод с сигнальным входом; срабатывает на событие,
  имеет состояние, выставляет выходы данных и испускает сигналы.
- **Latent node** (латентный нод) - исполняемый нод, завершающий работу позже: запрос
  эффекта исполняет адаптер, завершение приходит событием.
- **Virtual time** (виртуальное время) - единственные часы движка: `now` передаётся в
  тик снаружи, движок возвращает время следующего пробуждения.
- **Tick** (тик) - один вызов движка: применить правки и внешние события, доставить
  события до `now`, вернуть состояния, доставленные события, запросы эффектов и время
  пробуждения.
- **Effect request** (запрос эффекта) - просьба движка к адаптеру исполнить асинхронную
  работу латентного нода; несёт номер поколения.
- **Generation** (поколение) - номер запроса эффекта у экземпляра; завершение с
  устаревшим номером отбрасывается.
- **Capability** (возможность, `needs`, `env`) - доступ к API среды (fetch, файлы,
  случайность), который тип нода объявляет, а хост предоставляет.
- **Canonical node model** (каноническая модель нода, `NodeTypeDef` v2) - описание
  нода, которое исполняет движок; SDK отображаются в неё адаптерами.
- **Node SDK** (SDK нодов) - библиотека для авторов библиотек нодов: типы и хелперы для
  описания нодов; форма записи итерируется в лабе.
- **Lab** (лаба, spike) - исследовательский пакет `lab/` на отдельной ветке; в master не
  вливается, код выбрасывается, выводы переносятся в research и spec.
- **Reference engine** (эталонный интерпретатор, оракул) - простейшая реализация
  семантики для сравнения трасс с кандидатом движка.
- **Scenario** (сценарий, фикстура сценария) - граф плюс внешние события с виртуальным
  временем и ожидания; проверяется на эталоне и кандидате.
