● Понял. Судя по названию сессии «sdd», вас интересует в первую очередь
  spec-driven development. Расскажу про подходы и инструменты, которые сейчас
  популярны вокруг Claude Code. Мои знания заканчиваются серединой 2026 года, а
  в этой области всё быстро меняется, так что актуальность и звёзды на GitHub
  лучше проверить.

  Основные подходы

  1. Spec-Driven Development (SDD). Сначала пишется спецификация, потом код.
  Обычно цикл выглядит так:
  requirements → design → tasks → implementation
  Спека лежит в репозитории (specs/, .md файлы) и служит источником истины.
  Агент работает по ней, а не по разрозненным промптам из чата. Так меньше
  «дрейфа» от задачи, решения можно ревьюить до написания кода, и легче работать
  большими кусками.

  2. Explore → Plan → Code → Commit. Базовый цикл из рекомендаций Anthropic.
  Сначала агент читает код без правок, потом составляет план (Plan Mode,
  Shift+Tab), затем реализует и коммитит.

  3. TDD с агентом. Сначала тесты, которые падают, потом реализация до зелёного.
  Хорошо работает, потому что у агента есть чёткий критерий «готово».

  4. Context engineering. Управление тем, что попадает в контекст:
  - CLAUDE.md;
  - skills;
  - субагенты для изолированных задач;
  - регулярный /clear между задачами.

  5. Параллельная работа агентов. Несколько сессий в разных git worktree,
  оркестрация субагентов, фоновые и облачные агенты.

  SDD-фреймворки и инструменты

  Инструмент: GitHub Spec Kit
  Суть: CLI specify и команды /specify, /plan, /tasks. Есть «конституция»
  проекта
  (неизменяемые принципы). Работает с Claude Code, Copilot, Gemini CLI и др.
  ────────────────────────────────────────
  Инструмент: OpenSpec
  Суть: Более лёгкий SDD: изменения оформляются как «proposals» с дельтами к
  спекам. Удобен для существующих (brownfield) проектов.
  ────────────────────────────────────────
  Инструмент: BMAD Method
  Суть: Агенты с ролями (аналитик, PM, архитектор, scrum master, dev, QA). Из
  PRD
  и архитектуры получаются story-файлы, по которым идёт реализация.
  Тяжеловесный, но структурированный.
  ────────────────────────────────────────
  Инструмент: Kiro (AWS)
  Суть: Отдельная IDE, построенная вокруг SDD: requirements (EARS-формат) →
  design → tasks. Не Claude Code, но идеи часто переносят.
  ────────────────────────────────────────
  Инструмент: Agent OS
  Суть: Стандарты, продукт и спеки в виде файлов, которые агент подхватывает.
  ────────────────────────────────────────
  Инструмент: Task Master (claude-task-master)
  Суть: Разбивает PRD на задачи с зависимостями и ведёт агента по ним. Работает
  через MCP.
  ────────────────────────────────────────
  Инструмент: CCPM
  Суть: Project management для Claude Code через GitHub Issues: PRD → epic →
  issues → параллельные агенты в worktrees.

  Плагины и наборы для Claude Code

  - Superpowers (obra). Набор skills: brainstorming → написание плана →
    выполнение через субагентов, TDD, систематический дебаг. Очень популярен.
  - SuperClaude. Набор команд, персон и режимов поверх Claude Code.
  - claude-flow. Оркестрация роя агентов, ближе к экспериментальному.
  - Официальные плагины и маркетплейсы. Через /plugin можно ставить готовые
    наборы команд, агентов, hooks и skills.

  Встроенные механизмы Claude Code, на которых всё строится

  - Plan Mode. Сначала план, без правок.
  - Slash-команды (.claude/commands/). Так и реализованы /specify, /plan и
    подобные.
  - Субагенты (.claude/agents/). Роли с отдельным контекстом.
  - Skills. Подгружаемые инструкции под тип задачи.
  - Hooks. Автоматические проверки: линтер или тесты после правки.
  - MCP. Подключение трекеров, БД, документации.

  Что выбрать

  - Для небольшого проекта или старта хватит Plan Mode, CLAUDE.md и TDD.
  - Если хочется SDD без лишнего веса, подойдут Spec Kit или OpenSpec (для
    существующего кода).
  - Если нужна дисциплина процесса и качество, посмотрите Superpowers.
  - Для крупной фичи с командой или ролями есть BMAD или CCPM.

  Как устроен SDD

  Вы не просите сразу код, а проходите цепочку файлов. Каждый из них вы читаете
  и при необходимости правите:

  constitution → spec → clarify → plan → tasks → analyze → implement
   принципы      ЧТО     вопросы   КАК    шаги   проверка    код

  Главное правило: в spec описывается только что и зачем, без технологий. Стек
  появляется только на шаге plan.
