# Data Model: Визуальный редактор и реактивная среда выполнения DAG-workflow

**Feature**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md) | **Date**: 2026-10-05

Модель описана в терминах TypeScript-типов уровня движка (`src/engine/types.ts`).
Сохраняемые сущности (Workflow, CompositeDef, Workspace) сериализуются как есть
(см. [contracts/file-formats.md](./contracts/file-formats.md)).

## Значения и типы

```ts
type JsonValue = null | boolean | number | string | JsonValue[] | { [k: string]: JsonValue };
type PortType = 'number' | 'text' | 'boolean' | 'array' | 'object' | 'any';
```

**Правила**:
- значение соответствует типу: `number` — конечное число (без NaN и Infinity),
  `text` — строка, `boolean` — логическое, `array` — массив, `object` — объект (не
  массив и не null), `any` — любое JsonValue, включая null;
- совместимость при соединении: `a === b || a === 'any' || b === 'any'` (FR-005a).

## PortDef — описание порта

| Поле | Тип | Описание |
|---|---|---|
| `name` | string | уникально среди входов (или среди выходов) нода; 1–40 символов (_уточнено в 003: ограничение длины снято, только непустое_) |
| `type` | PortType | тип данных |
| `required` | boolean | только для входов: незаполненный вход (нет связи, нет значения в `values`, нет `default`) переводит нод в `waiting`; `null` — обычное значение (FR-017) |
| `default` | JsonValue? | только для входов: значение, если вход не подключён и не задан вручную |

## NodeTypeDef — тип нода

| Поле | Тип | Описание |
|---|---|---|
| `id` | string | `builtin:<имя>` для встроенных, `composite:<uuid>` для составных |
| `title` | string | отображаемое имя |
| `category` | string | категория в палитре |
| `description` | string | краткое описание для палитры (FR-001) |
| `inputs` | PortDef[] | входы |
| `outputs` | PortDef[] | выходы |
| `compute` | `(inputs: Record<string, JsonValue>) => Record<string, JsonValue>` | только у встроенных; чистая синхронная функция; бросает `NodeError` |

Для составных нодов `inputs` и `outputs` **вычисляются** из нодов «Вход» и «Выход»
определения (FR-021a, FR-021b), а не хранятся.

## NodeInstance — нод в графе

| Поле | Тип | Описание |
|---|---|---|
| `id` | string | uuid, уникален в графе |
| `type` | string | ссылка на `NodeTypeDef.id` |
| `position` | `{x: number, y: number}` | позиция на холсте |
| `values` | `Record<string, JsonValue>` | вручную заданные значения входов (FR-007) |
| `ports` | PortDef[]? | только у нодов `builtin:input` / `builtin:output` внутри составного нода: порты, которые этот нод добавляет в интерфейс (FR-021a) |

**Правила**: ключи `values` — имена входов этого нода; значение соответствует типу
порта. Значение для подключённого входа игнорируется (вход берёт значение из связи).

_Уточнено в [002](../002-editor-ui-redesign/data-model.md#nodeinstance--нод-в-графе-изменение): у нода есть обязательное поле `name` — имя экземпляра (1–100 символов, при создании — название типа)._

## Edge — связь

| Поле | Тип | Описание |
|---|---|---|
| `id` | string | uuid |
| `source` | `{node: string, port: string}` | выходной порт |
| `target` | `{node: string, port: string}` | входной порт |

**Правила** (проверяет `canConnect`):
- оба нода и порта существуют, source — выход, target — вход;
- типы совместимы (FR-005a);
- связь не создаёт цикл (FR-004);
- на один вход не больше одной связи. Новая связь на занятый вход заменяет старую
  (edge case);
- связь нода самого с собой запрещена (частный случай цикла).

## Graph — граф

| Поле | Тип |
|---|---|
| `nodes` | NodeInstance[] |
| `edges` | Edge[] |

**Инвариант**: граф ациклический (DAG). Он проверяется при каждой правке и при
импорте.

## Workflow

| Поле | Тип | Описание |
|---|---|---|
| `id` | string | uuid |
| `name` | string | 1–100 символов; уникальность не требуется (_уточнено в 003: ограничение длины снято, только непустое_) |
| `graph` | Graph | ноды и связи |
| `createdAt` / `updatedAt` | string (ISO 8601) | метки времени |

**Правила**: ноды `builtin:input` и `builtin:output` в workflow верхнего уровня
запрещены, они бывают только внутри составных нодов.

## CompositeDef — определение составного нода

| Поле | Тип | Описание |
|---|---|---|
| `id` | string | uuid; тип нода — `composite:<id>` |
| `name` | string | 1–100 символов (_уточнено в 003: ограничение длины снято, только непустое_); уникально в палитре (FR-023a): при сворачивании и переименовании занятое имя отклоняется, при конфликте импорта получает суффикс « (2)», « (3)»… |
| `description` | string | необязательное описание |
| `graph` | Graph | внутренний граф, может содержать `builtin:input` / `builtin:output` и другие составные ноды |
| `createdAt` / `updatedAt` | string (ISO 8601) | метки времени |

**Правила**:
- имена портов уникальны среди всех нодов «Вход» и отдельно среди всех нодов
  «Выход» (FR-021c);
- порядок портов определяется порядком нодов «Вход»/«Выход» в `graph.nodes`, затем
  порядком `ports` внутри нода (FR-021b);
- граф зависимостей определений ациклический: нельзя прямо или косвенно включить
  себя (FR-026);
- «содержательное равенство» для слияния при импорте (FR-029a) — равенство
  канонического JSON полей `name`, `description` и `graph`.

## Workspace — состояние рабочего пространства

| Поле | Тип | Описание |
|---|---|---|
| `workflowOrder` | string[] | порядок workflow в списке |
| `tabs` | Tab[] | открытые вкладки |
| `activeTabId` | string \| null | активная вкладка |

## Tab — вкладка (не входит в файл выгрузки)

| Поле | Тип | Описание |
|---|---|---|
| `id` | string | uuid |
| `kind` | `'workflow' \| 'composite'` | что редактируется |
| `targetId` | string | id workflow или CompositeDef |
| `viewport` | `{x, y, zoom}` | положение холста |

История отмены (стек снапшотов Graph, ≤ 100) живёт только в памяти, отдельно для
каждой вкладки (FR-009, FR-031a). Повторное открытие той же цели переключает на
существующую вкладку.

## NodeState — состояние вычисления (только в памяти)

| Поле | Тип | Описание |
|---|---|---|
| `status` | `'ok' \| 'computing' \| 'waiting' \| 'error' \| 'blocked'` | FR-016 |
| `inputs` | `Record<string, JsonValue>` | фактические значения входов |
| `outputs` | `Record<string, JsonValue>` | значения выходов (при `ok`) |
| `message` | string? | при `error` — текст ошибки; при `waiting` — какой вход не заполнен; при `blocked` — какой нод выше по графу не вычислен и почему |

### Переходы состояний

```text
                  изменение входа/структуры
   ┌──────────────────────────────────────────────┐
   ▼                                              │
computing ──(все входы есть, compute ок)──────▶ ok ┤
   │                                              │
   ├──(обязательный вход пуст)──────────────▶ waiting
   ├──(compute бросил NodeError)────────────▶ error
   └──(источник в error/waiting/blocked)────▶ blocked
```

- `waiting`, `error` и `blocked` не терминальные: при устранении причины нод
  автоматически снова проходит через `computing` (FR-019);
- `blocked` отображается как «не вычислен: проблема выше по графу»; источник может быть в `error`, `waiting` или
  `blocked`.
- Сводный статус экземпляра составного нода — по приоритету: есть `error` → `error`, иначе есть `waiting` → `waiting`, иначе есть `blocked` → `blocked`, иначе есть `computing` → `computing`, иначе `ok` (сводный статус показывает первопричину, а не её следствия).

## StorageLocation — где хранятся данные

| Значение | Описание |
|---|---|
| `{kind: 'folder', name: string}` | выбранная папка (FileSystemDirectoryHandle в IndexedDB) |
| `{kind: 'folder-pending', name: string}` | папка выбрана, но браузер требует повторного подтверждения доступа; данные не загружаются и не записываются, показывается экран восстановления доступа (FR-028d) |
| `{kind: 'browser'}` | внутреннее хранилище браузера (OPFS) |
| `{kind: 'none', reason: string}` | хранилище недоступно (например, приватный режим): работа без сохранения, баннер с предложением выгружать в файл |

## Связи между сущностями

```text
Workspace 1 ──── * Workflow ──── 1 Graph ──── * NodeInstance ──── * Edge
    │                                              │ type
    │                                              ▼
    └── * CompositeDef ──── 1 Graph         NodeTypeDef (builtin | composite)
    └── * Tab ──▶ Workflow | CompositeDef
```
