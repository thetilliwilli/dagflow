# Backlog: отложенные фичи

Фичи, о которых договорились, но которые ещё не начаты. Это соглашение проекта, а
не артефакт Spec Kit. Как пользоваться:

- Новая фича начинается на `master` командой `/speckit-specify` с текстом из
  поля «Описание для /speckit-specify».
- Начатая фича удаляется отсюда в том же коммите, где появляется её `spec.md`.
  Источником истины становится каталог `specs/NNN-…/`.
- Номер фичи здесь предварительный: его выдаёт `/speckit-specify` по порядку.

## Защита сервера выполнения

- **Откуда**: обсуждение архитектуры удалённого engine (2026-10-07). В первой фиче
  сервер осознанно открыт для любого Origin: WebSocket без проверки `Origin`, HTTP-ответы
  с `Access-Control-Allow-Origin: *`. Сейчас это безопасно: ноды чистые, документы
  изолированы по соединению, сервер ничего не хранит.
- **Когда начинать**: обязательно до фичи, которая даёт нодам на сервере эффекты
  (`fetch`, файлы и т. п.) или общее состояние между соединениями. Без неё такие
  возможности не включать.
- **Описание для /speckit-specify**: Защита сервера выполнения workflow от
  посторонних клиентов. Сайты, открытые в браузере пользователя, и программы в сети
  не должны без разрешения запускать workflow на сервере и пользоваться его
  возможностями. Пользователь решает, какие клиенты допускаются.
- **Заметки к плану**: проверка заголовка `Origin` при WebSocket-рукопожатии (список
  разрешённых, флаг CLI) защищает только от сайтов в браузере (cross-site WebSocket
  hijacking); от программ вне браузера — токен / аутентификация (нужна поправка к
  конституции: раздел «Ограничения»). Учесть DNS rebinding (проверка `Host`).
