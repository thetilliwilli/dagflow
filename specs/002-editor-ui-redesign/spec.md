**Feature Branch**: `002-editor-ui-redesign`

**Created**: 2026-10-05

**Status**: Draft

**Input**: User description: "список доработок для редактора графов:

2. у нодов не должно быть скругления углов - они прямоугольные

12. крайняя левая панель - скрыта в кнопке сендвиче - когда нажимаю на кнопку это окно появляется плавающим поверх окна с графами

## Clarifications

### Session 2026-10-05

- Q: Браузер не раскрывает полный путь к выбранной папке — как быть с пунктом 10?
  → A: Пункт снят: в левой панели остаётся «Папка: &lt;имя папки&gt;», как сейчас.
- Q: Что, кроме типа и имени, остаётся на карточке нода? → A: Значок состояния и
  короткий текст проблемы (какой вход не заполнен, текст ошибки). Значения портов,
  в том числе результат «Показать», — только в property grid.
- Уточнение пользователя: недоступные для броска параметры затеняются (серые), но
  не исчезают из окна — интерфейс не должен «прыгать».
- Уточнение пользователя: строка параметра в property grid —
  `[маркер] [тип] [имя] [значение]`. Маркер — квадратная кнопка с рамкой: зелёная
  заливка, если параметр связан, серая — если нет. Щелчок по маркеру включает режим
  привязки: затем пользователь выбирает другой нод и завершает связь щелчком по
  параметру этого нода. Тип — краткое обозначение: num, str, bool, arr, obj, any.

## Контекст

Фича меняет облик и способ работы с редактором из фичи `001-dag-workflow-editor`.
Возможности 001 (реактивное вычисление, типы портов, запрет циклов, составные
ноды, сохранение, вкладки, отмена) сохраняются полностью; меняется то, как
пользователь их видит и как с ними взаимодействует. Требования 001, которые эта
фича уточняет или заменяет, перечислены в разделе «Связь с фичей 001».

Образец внешнего вида — схемы из двух скриншотов пользователя: прямоугольные
ноды с серым типом в левом верхнем углу и именем по центру; прямые линии со
стрелкой между нодами и подписями «свойство→свойство» у линии.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Холст во весь экран и плавающие окна (Priority: P1)

Пользователь открывает редактор и видит всю рабочую область занятой вкладками
workflow и холстом. Ничего лишнего не отнимает место: список workflow и
хранилище спрятаны за кнопкой меню в левом верхнем углу, палитра вызывается
клавишей Пробел, свойства нода показываются, когда нод выделен. Все эти окна
плавающие: они появляются поверх холста и не мешают продолжать работать с ним.

**Why this priority**: это каркас нового интерфейса, на который опираются все
остальные истории (property grid, связывание, палитра). Без него остальные
доработки некуда встроить.

**Independent Test**: открыть редактор, убедиться, что холст с вкладками занимает
всё окно; нажать кнопку меню — появляется левая панель со списком workflow,
поверх холста; холст при этом можно перемещать; нажать Пробел — появляется
палитра с вкладками категорий; добавить из неё нод.

**Acceptance Scenarios**:

1. **Given** редактор открыт, **When** пользователь ничего не нажимал, **Then**
   всё окно редактора занимают полоса вкладок workflow и холст активной вкладки,
   а в левом верхнем углу видна кнопка меню.
2. **Given** левая панель скрыта, **When** пользователь нажимает кнопку меню,
   **Then** левая панель (хранилище, список workflow, выгрузка и загрузка)
   появляется плавающим окном поверх холста; повторное нажатие кнопки, кнопка
   закрытия панели или клавиша Escape её скрывают.
3. **Given** фокус на холсте (не в поле ввода), **When** пользователь нажимает
   Пробел, **Then** появляется плавающее окно палитры с вкладками по категориям
   нодов; повторный Пробел, кнопка закрытия или Escape её скрывают.
4. **Given** открыта палитра, **When** пользователь переключает вкладку категории,
   **Then** видны только ноды этой категории с кратким описанием, входами и
   выходами.
5. **Given** открыта палитра, **When** пользователь перетаскивает нод из неё на
   холст или щёлкает по ноду, **Then** нод появляется на холсте (в точке броска
   или в центре видимой области), а палитра остаётся открытой.
6. **Given** открыто любое плавающее окно, **When** пользователь перемещает,
   масштабирует холст или выделяет ноды за пределами окна, **Then** холст
   реагирует как обычно: плавающее окно не блокирует работу.
7. **Given** плавающее окно открыто, **When** пользователь перетаскивает его за
   заголовок, **Then** окно перемещается и остаётся в пределах окна редактора.
8. **Given** фокус в поле ввода (например, при вводе значения или имени),
   **When** пользователь нажимает Пробел, **Then** вводится пробел, палитра не
   открывается.

### User Story 2 - Новый вид нодов и выделение (Priority: P1)

Нод на холсте — строгий прямоугольник без скруглений. В левом верхнем углу
серым мелким текстом написан тип нода, по центру — имя этого экземпляра.
Пользователь может переименовать любой нод, чтобы граф читался как схема
бизнес-логики («сразу по окончании дня», «текст отчёта на почту»). Выделенный
нод заметно отличается: его рамка становится синей.

**Why this priority**: имена экземпляров и чистый вид нодов — основа читаемости
графа; это самая заметная пользователю доработка, и она нужна для подписей
связей и property grid.

**Independent Test**: добавить нод «Сложить», убедиться, что сверху слева серым
написано «Сложить», по центру — имя «Сложить»; переименовать его в «Итого»,
закрыть и снова открыть редактор — имя «Итого» на месте, тип по-прежнему
«Сложить»; выделить нод — рамка синяя, снять выделение — рамка обычная.

**Acceptance Scenarios**:

1. **Given** пустой холст, **When** пользователь добавляет нод, **Then** нод
   отображается прямоугольником без скругления углов, с типом нода серым текстом
   в левом верхнем углу и именем экземпляра по центру; новое имя по умолчанию
   совпадает с названием типа.
2. **Given** нод на холсте, **When** пользователь переименовывает его (двойным
   щелчком по имени на ноде или в property grid) и подтверждает ввод, **Then** по
   центру нода показывается новое имя, а тип в углу не меняется.
3. **Given** нод переименован, **When** пользователь выбирает «Отменить», **Then**
   возвращается прежнее имя.
4. **Given** пользователь переименовывает нод, **When** он вводит пустое имя или
   нажимает Escape, **Then** имя не меняется.
5. **Given** нод переименован, **When** workflow сохраняется, выгружается в файл
   и загружается обратно, **Then** имя экземпляра сохраняется.
6. **Given** нод не выделен, **When** пользователь выделяет его, **Then** рамка
   нода становится синей; при снятии выделения рамка возвращается к обычному
   цвету. При выделении нескольких нодов синяя рамка у каждого из них.
7. **Given** нод в состоянии ошибки или ожидания входов, **When** пользователь
   смотрит на холст, **Then** на самом ноде видно его состояние (по FR-016 фичи
   001), и оно отличимо от выделения.

### User Story 3 - Property grid выделенного нода (Priority: P1)

Когда пользователь выделяет нод, рядом появляется плавающее окно свойств
(property grid). В нём две панели одна под другой: «Входы» и «Выходы» — со
списком параметров нода, их типами и текущими значениями. Здесь же пользователь
задаёт вручную значения неподключённых входов и видит, откуда пришло значение
подключённого входа.

**Why this priority**: значения портов и ручной ввод переезжают с карточки нода
в property grid; без него редактор теряет возможности фичи 001.

**Independent Test**: собрать граф «Число 2» → «Сложить» ← «Число 3»; выделить
«Сложить» — появляется окно с панелями «Входы» (a = 2, b = 3, оба подключены) и
«Выходы» (результат = 5); выделить «Число 2», изменить значение на 10 в property
grid; выделить «Сложить» — результат 13.

**Acceptance Scenarios**:

1. **Given** на холсте нод, **When** пользователь выделяет его (один нод),
   **Then** появляется плавающее окно с именем и типом нода и двумя панелями
   одна под другой: «Входы» и «Выходы». Каждый параметр — строка
   `[маркер] [тип] [имя] [значение]`: маркер — квадратная кнопка с рамкой
   (зелёная заливка — параметр связан, серая — не связан), тип — краткое
   обозначение (num, str, bool, arr, obj, any).
2. **Given** открыт property grid нода, **When** значение любого его параметра
   меняется (из-за пересчёта графа), **Then** новое значение видно в окне сразу,
   без повторного выделения.
3. **Given** вход нода не подключён, **When** пользователь вводит его значение в
   property grid, **Then** значение применяется и граф пересчитывается (FR-007
   фичи 001, включая массивы и объекты).
4. **Given** вход подключён связью, **When** пользователь смотрит на него в
   property grid, **Then** видно, от какого нода и какого его выхода приходит
   значение, а ручной ввод для этого входа недоступен.
5. **Given** у нода нет входов (или выходов), **When** открыт его property grid,
   **Then** соответствующая панель показывает, что параметров нет.
6. **Given** открыт property grid, **When** пользователь снимает выделение
   (щелчок по пустому месту холста или Escape), **Then** окно скрывается; при
   выделении другого нода окно показывает его свойства.
7. **Given** выделено несколько нодов, **When** пользователь смотрит на экран,
   **Then** property grid не показывается.
8. **Given** выделен составной нод или нод «Вход»/«Выход», **When** открыт
   property grid, **Then** в нём доступны действия, которые раньше были на
   карточке нода: открыть и развернуть составной нод; добавить, удалить,
   переименовать порт и сменить его тип у нода «Вход»/«Выход».
9. **Given** нод в состоянии ошибки или ожидания входов, **When** открыт его
   property grid, **Then** в окне показано понятное описание проблемы (какой
   вход не заполнен или что за ошибка).

### User Story 4 - Связывание свойств перетаскиванием (Priority: P2)

Чтобы связать два нода, пользователь выделяет первый нод, берёт в его property
grid нужный параметр и тащит его на другой нод. Когда курсор оказывается над
вторым нодом, рядом с ним появляется его property grid; пользователь отпускает
параметр над подходящим параметром второго нода. Вместо перетаскивания можно
щёлкнуть по маркеру параметра — включится режим привязки, — затем выбрать другой
нод и щёлкнуть по нужному параметру в его окне. Редактор сам следит, чтобы
выход соединялся со входом и типы были совместимы, и заранее затеняет
параметры, к которым привязать нельзя, не убирая их из окна.

**Why this priority**: это новый способ создавать связи — без него в новом
интерфейсе нельзя собрать граф. Стоит после P1, потому что опирается на новый
вид нодов и property grid.

**Independent Test**: выделить «Число 2», перетащить его выход «значение» на нод
«Сложить», дождаться его property grid, бросить на вход «a» — связь создана,
«Сложить» пересчитался. Повторить с выходом типа «текст» на вход типа «число» —
вход отмечен как недоступный, при броске связь не создаётся, показывается
объяснение.

**Acceptance Scenarios**:

1. **Given** выделен нод A и открыт его property grid, **When** пользователь
   начинает тащить параметр из панели «Выходы», **Then** видно, что идёт
   связывание (за курсором следует метка параметра), а холст при этом не
   сдвигается.
2. **Given** идёт перетаскивание выхода нода A, **When** курсор оказывается над
   нодом B, **Then** рядом с B появляется временный property grid нода B, в
   котором доступны для броска только входы, совместимые по типу (FR-005a фичи
   001) и не создающие цикла; остальные параметры затенены (серые), но остаются
   на своих местах — состав и порядок строк окна не меняются.
3. **Given** временный property grid нода B открыт, **When** пользователь
   отпускает выход A над совместимым входом B, **Then** связь A → B создаётся,
   B пересчитывается, временное окно скрывается, а выделенным остаётся нод A.
4. **Given** идёт перетаскивание входа нода A (из панели «Входы»), **When**
   пользователь отпускает его над совместимым выходом нода B, **Then** создаётся
   связь от выхода B ко входу A.
5. **Given** идёт перетаскивание, **When** пользователь отпускает параметр над
   недоступным параметром, **Then** связь не создаётся и показывается понятное
   объяснение (несовместимые типы, вход со входом, выход с выходом, цикл).
6. **Given** идёт перетаскивание, **When** пользователь отпускает параметр над
   пустым местом холста или нажимает Escape, **Then** ничего не меняется.
7. **Given** вход B уже подключён к другому источнику, **When** пользователь
   бросает на него новый выход, **Then** старая связь заменяется новой (как в
   фиче 001); действие можно отменить.
8. **Given** идёт перетаскивание, **When** курсор уходит с нода B на нод C,
   **Then** временное окно B скрывается и появляется окно C.
9. **Given** открыт property grid нода A, **When** пользователь щёлкает по
   маркеру параметра, **Then** включается режим привязки: маркер и строка
   параметра выделены, видна подсказка «Выберите нод и параметр для связи».
10. **Given** включён режим привязки от параметра нода A, **When** пользователь
    щёлкает по ноду B (или наводит на него курсор), **Then** появляется окно
    свойств B с затенёнными недоступными параметрами; щелчок по доступному
    параметру создаёт связь и завершает режим привязки, а выделенным остаётся A.
11. **Given** включён режим привязки, **When** пользователь щёлкает по
    затенённому параметру, **Then** связь не создаётся, показывается понятное
    объяснение, режим привязки продолжается.
12. **Given** включён режим привязки, **When** пользователь нажимает Escape,
    щёлкает по пустому месту холста или ещё раз по тому же маркеру, **Then**
    режим привязки завершается без изменений графа.
13. **Given** вход не связан, **When** пользователь создаёт к нему связь,
    **Then** маркер входа и маркер выхода-источника становятся зелёными; при
    удалении последней связи параметра его маркер снова серый.

### User Story 5 - Одна линия между нодами с подписями связей (Priority: P2)

Между двумя нодами рисуется одна прямая линия со стрелкой в сторону получателя,
сколько бы связей между ними ни было. Рядом с линией подписан список всех
связей вида «выход→вход». Щелчок по линии открывает окно со списком этих связей,
где любую можно удалить крестиком.

**Why this priority**: делает граф читаемым как схема и заменяет пучки
отдельных кривых линий; удаление связей нужно для полноценной работы, но
создание связей (US4) важнее.

**Independent Test**: связать выходы «результат» нода A со входами «день» и
«запуск» нода B — между A и B одна прямая линия со стрелкой к B и подписью из
двух строк «результат→день», «результат→запуск»; щёлкнуть по линии, удалить
крестиком «результат→запуск» — подпись осталась из одной строки, B пересчитан;
удалить последнюю связь — линия исчезла.

**Acceptance Scenarios**:

1. **Given** два нода, **When** между ними есть хотя бы одна связь, **Then** они
   соединены одной прямой линией со стрелкой, направленной к ноду-получателю.
2. **Given** между нодами A и B несколько связей, **When** пользователь смотрит
   на холст, **Then** рядом с линией показан список всех связей, по одной в
   строке, в виде «выход→вход» (имена параметров).
3. **Given** ноды перемещаются, **When** пользователь тянет один из нодов,
   **Then** линия остаётся прямой и подпись следует за ней.
4. **Given** линия между A и B, **When** пользователь щёлкает по линии или по её
   подписи, **Then** появляется плавающее окно со списком всех связей A → B, у
   каждой — кнопка удаления (крестик).
5. **Given** открыто окно связей, **When** пользователь нажимает крестик у одной
   связи, **Then** удаляется только эта связь, получатель пересчитывается, список
   и подпись обновляются; если связь была последней, линия и окно исчезают.
6. **Given** связь удалена крестиком, **When** пользователь выбирает «Отменить»,
   **Then** связь возвращается.
7. **Given** окно связей открыто, **When** пользователь щёлкает по пустому месту
   холста, нажимает Escape или кнопку закрытия, **Then** окно скрывается.

---

### Edge Cases

- Плавающее окно перекрывает выделенный нод или нод, на который идёт бросок:
  окно размещается рядом с нодом так, чтобы нод оставался видимым; если места
  нет, пользователь может сдвинуть окно или холст.
- Окно редактора уменьшили: открытые плавающие окна остаются в пределах окна
  редактора.
- Открыты одновременно палитра, левая панель и property grid: все остаются
  работоспособными; последнее открытое или активированное окно — поверх
  остальных.
- Пробел нажат во время перетаскивания параметра или переименования нода:
  палитра не открывается.
- Переключение вкладки workflow: property grid и окно связей закрываются,
  выделение принадлежит вкладке.
- Нод удалён, пока открыт его property grid (например, отменой действия): окно
  скрывается.
- Связь удалена другим способом (удалением нода, отменой), пока открыто окно
  связей: список обновляется; если связей не осталось, окно скрывается.
- Очень длинное имя нода или параметра: имя на ноде и в подписях укорачивается
  с многоточием, полный текст виден во всплывающей подсказке и в property grid.
- Между двумя нодами много связей (больше 5): подпись показывает первые 5 и
  строку «ещё N»; полный список — в окне связей.
- Два нода с одинаковыми именами: допустимо, имена экземпляров не обязаны быть
  уникальными (ноды различаются положением и связями).
- Нод «Показать» (отображение результата): его значение видно в property grid
  при выделении нода; на карточке — только тип, имя и состояние (FR-008).
- В режиме привязки пользователь начинает перетаскивать другой параметр: режим
  привязки завершается, начинается перетаскивание.
- В режиме привязки пользователь переключает вкладку workflow: режим привязки
  завершается без изменений.
- Файлы workflow, сохранённые до этой фичи (без имён экземпляров), открываются
  без ошибок: имя каждого нода равно названию его типа.
- Перетаскивание параметра (или режим привязки) на свой же нод: все параметры
  затенены, связь не создаётся.
- Перетаскивание параметра на нод с неизвестным типом (удалённый составной нод):
  нод недоступен для броска.

## Requirements *(mandatory)*

### Functional Requirements

**Рабочая область и плавающие окна**

- **FR-001**: Рабочую область редактора ДОЛЖНЫ целиком занимать полоса вкладок
  workflow и холст активной вкладки. Остальные окна (левая панель, палитра,
  property grid, окно связей) ДОЛЖНЫ появляться плавающими поверх холста только
  по своему вызову.
- **FR-002**: Плавающие окна НЕ ДОЛЖНЫ блокировать холст: пока окно открыто,
  пользователь может перемещать и масштабировать холст, выделять и двигать ноды
  вне окна.
- **FR-003**: Каждое плавающее окно ДОЛЖНО иметь заголовок с кнопкой закрытия,
  перемещаться перетаскиванием заголовка и оставаться в пределах окна редактора.
  Клавиша Escape закрывает последнее открытое окно.
- **FR-004**: В левом верхнем углу ДОЛЖНА быть кнопка меню; её нажатие
  показывает и скрывает левую панель с содержимым прежней боковой панели
  (место хранения и выбор папки, список workflow, выгрузка и загрузка).
- **FR-005**: Клавиша Пробел, нажатая не в поле ввода, ДОЛЖНА показывать и
  скрывать палитру нодов. Палитра — плавающее окно с вкладками по категориям
  нодов; в каждой вкладке — ноды категории с кратким описанием, входами и
  выходами (FR-001 фичи 001). Составные ноды — отдельная вкладка с прежними
  действиями (открыть, переименовать, удалить).
- **FR-006**: Нод из палитры ДОЛЖЕН добавляться перетаскиванием на холст (в точку
  броска) или щелчком (в центр видимой области); палитра после добавления
  остаётся открытой.
- **FR-006a**: Предложения и предупреждения о хранилище (выбор папки, перенос,
  восстановление, недоступность хранения) ДОЛЖНЫ показываться без участия левой
  панели — как неблокирующие уведомления поверх холста.

**Вид нодов**

- **FR-007**: Нод ДОЛЖЕН отображаться прямоугольником без скругления углов; в
  левом верхнем углу — тип нода (название типа) серым текстом меньшего размера,
  по центру — имя экземпляра.
- **FR-008**: Помимо типа и имени, на карточке нода ДОЛЖНЫ быть видны значок
  состояния вычисления (FR-016 фичи 001), отличимый от выделения, и — если нод
  ожидает входов или завершился ошибкой — короткий текст проблемы (какой вход не
  заполнен, текст ошибки). Значения портов на карточке не показываются.
- **FR-009**: Каждый нод ДОЛЖЕН иметь имя экземпляра; при добавлении имя равно
  названию типа. Пользователь ДОЛЖЕН иметь возможность переименовать нод двойным
  щелчком по имени на холсте и в property grid. Пустое имя не принимается;
  длина имени — до 100 символов; уникальность не требуется.
- **FR-010**: Имя экземпляра ДОЛЖНО сохраняться вместе с workflow, входить в
  выгрузку в файл и восстанавливаться при загрузке; переименование отменяется и
  повторяется как любое действие редактирования. Файлы без имён экземпляров
  загружаются, имя берётся из названия типа.
- **FR-011**: Выделенный нод ДОЛЖЕН отображаться синей рамкой, отличимой от
  рамок состояний вычисления; при множественном выделении синюю рамку получает
  каждый выделенный нод.

**Property grid**

- **FR-012**: При выделении ровно одного нода ДОЛЖНО появляться плавающее окно
  свойств рядом с нодом; при снятии выделения или выделении нескольких нодов
  окно скрывается.
- **FR-013**: Окно свойств ДОЛЖНО показывать имя и тип нода и две панели одна
  под другой: «Входы» и «Выходы». В каждой — параметры нода по порядку портов,
  по строке на параметр: `[маркер] [тип] [имя] [значение]`. Большие значения —
  компактно с возможностью раскрыть (FR-007a фичи 001).
- **FR-013a**: Маркер параметра ДОЛЖЕН быть квадратной кнопкой с рамкой: с
  зелёной заливкой, если у параметра есть хотя бы одна связь, и с серой — если
  связей нет. Маркер обновляется сразу при создании и удалении связей.
- **FR-013b**: Тип параметра ДОЛЖЕН показываться кратким обозначением: num
  (число), str (текст), bool (логическое), arr (массив), obj (объект), any
  («любое»); полное название типа — во всплывающей подсказке.
- **FR-014**: Значения в окне свойств ДОЛЖНЫ обновляться в реальном времени при
  пересчёте графа.
- **FR-015**: Для неподключённого входа окно свойств ДОЛЖНО позволять задать
  значение вручную (FR-007 фичи 001); для подключённого — показывать источник
  (имя нода и его выхода) и не давать ручного ввода.
- **FR-016**: Окно свойств ДОЛЖНО показывать состояние нода и понятное описание
  проблемы, если нод ожидает входов или завершился ошибкой.
- **FR-017**: Действия над нодом, которые раньше были на его карточке, ДОЛЖНЫ
  быть доступны в окне свойств: открыть и развернуть составной нод; управление
  портами нодов «Вход» и «Выход» (добавить, удалить, переименовать, сменить тип,
  задать значение по умолчанию).

**Связывание перетаскиванием**

- **FR-018**: Связь ДОЛЖНА создаваться перетаскиванием параметра из окна
  свойств выделенного нода на другой нод: при наведении на нод появляется его
  временное окно свойств, и бросок на параметр в этом окне создаёт связь.
- **FR-018a**: Щелчок по маркеру параметра ДОЛЖЕН включать режим привязки:
  пользователь выбирает другой нод (щелчком или наведением), в появившемся окне
  свойств щёлкает по параметру, и связь создаётся по тем же правилам, что и при
  перетаскивании (FR-019 – FR-022). Escape, щелчок по пустому месту холста или
  повторный щелчок по маркеру завершают режим без изменений; щелчок по
  недоступному параметру показывает объяснение и режим не завершает.
- **FR-019**: Перетаскивать (и привязывать щелчком) можно и выход, и вход: связь всегда идёт от выхода
  к входу. Бросок выхода на выход и входа на вход ДОЛЖЕН быть недоступен.
- **FR-020**: Во время перетаскивания и в режиме привязки окно свойств
  другого нода ДОЛЖНО заранее затенять (показывать серыми) параметры, с которыми
  связать нельзя (не та сторона, несовместимый тип по FR-005a фичи 001, цикл по
  FR-004 фичи 001, тот же нод). Затенённые параметры остаются на своих местах:
  состав, порядок и размеры строк окна не меняются. Бросок или щелчок на такой
  параметр не создаёт связь и показывает понятное объяснение.
- **FR-021**: Бросок на пустое место холста или Escape во время перетаскивания
  ДОЛЖЕН отменять связывание без изменений графа.
- **FR-022**: Бросок на уже подключённый вход ДОЛЖЕН заменять прежнюю связь
  (как в фиче 001); создание и замена связи отменяются как обычные действия.

**Линии связей**

- **FR-023**: Все связи от нода A к ноду B ДОЛЖНЫ отображаться одной прямой
  линией со стрелкой к B.
- **FR-024**: Рядом с линией ДОЛЖЕН показываться список связей в виде
  «выход→вход» (имена параметров), по одной связи в строке; при большом числе
  связей — первые 5 и строка «ещё N».
- **FR-025**: Щелчок по линии или её подписи ДОЛЖЕН открывать плавающее окно со
  списком всех связей между этими нодами; у каждой связи — кнопка удаления
  (крестик), удаляющая только её. Удаление отменяется как обычное действие.

### Связь с фичей 001

Эта фича уточняет требования `001-dag-workflow-editor`. Чтобы артефакты 001
оставались источником истины (принцип V), у затронутых требований в spec.md
фичи 001 ставится пометка «уточнено в 002» со ссылкой на эту спецификацию;
действующими считаются формулировки ниже.

- FR-001 (001), палитра: показывается плавающим окном по Пробелу (FR-005, FR-006).
- FR-003 (001), соединение портов: вместо протягивания линии от порта к порту на
  холсте — перетаскивание параметров между окнами свойств (FR-018 – FR-022).
- FR-006 (001), удаление связи: через окно связей (FR-025).
- FR-007, FR-007a, FR-015 (001), значения на ноде: ручной ввод и текущие
  значения входов и выходов — в окне свойств (FR-013 – FR-015); на карточке —
  по FR-008.
- FR-016, FR-018 (001), состояние и ошибка «на ноде»: значок состояния и
  короткий текст проблемы — на карточке (FR-008), подробности — в окне свойств
  (FR-016); SC-006 (001) продолжает выполняться.
- FR-031 (001), список workflow: находится в левой панели за кнопкой меню
  (FR-004).

### Key Entities

- **Нод**: к атрибутам из фичи 001 добавляется **имя экземпляра** — текст до 100
  символов, по умолчанию равный названию типа; хранится в workflow.
- **Пучок связей**: все связи от одного нода к другому; отображается одной
  линией с подписью и открывает окно связей. Не хранится отдельно — выводится из
  связей графа.
- **Плавающее окно**: левая панель, палитра, окно свойств, временное окно
  свойств при связывании, окно связей. Положение окон и открытая вкладка палитры
  не сохраняются между сессиями.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: При закрытых плавающих окнах холст с вкладками занимает 100%
  рабочей области окна редактора (кроме полосы вкладок и кнопки меню).
- **SC-002**: Пользователь, знакомый с фичей 001, без подсказок создаёт связь
  между двумя нодами новым способом с первой попытки не дольше чем за 15 секунд.
- **SC-003**: 100% попыток связать параметр с несовместимым отклоняются, и
  пользователь видит затенение недоступного параметра ещё до броска или щелчка;
  при этом строки окна свойств не сдвигаются.
- **SC-004**: Между любыми двумя нодами отображается не больше одной линии, и
  каждая связь графа видна в подписи или в окне связей — 100% связей.
- **SC-005**: Окно свойств появляется при выделении нода, а временное окно —
  при наведении на нод во время связывания, без заметной задержки (менее 0,1 с)
  на графе из 100 нодов.
- **SC-006**: Пользователь может удалить конкретную связь из пучка не больше
  чем за 2 действия (щелчок по линии, щелчок по крестику).
- **SC-009**: По маркерам окна свойств пользователь в 100% случаев правильно
  определяет, какие параметры нода связаны, не глядя на линии холста.
- **SC-007**: В 100% случаев выгрузка и загрузка workflow сохраняют имена
  экземпляров нодов; workflow, сохранённые до этой фичи, открываются без ошибок.
- **SC-008**: Требования SC-002 и SC-003 фичи 001 (отклик редактирования и
  пересчёта на графе из 100 нодов) продолжают выполняться.

## Assumptions

- Все возможности фичи 001 сохраняются; меняется только представление и способ
  взаимодействия. Мини-карта, вкладки, отмена и горячие клавиши отмены остаются.
- На карточке нода больше нет портов-«ручек» для протягивания связей: связать
  параметры можно только в окнах свойств — перетаскиванием или режимом привязки
  по маркеру (US4).
- Пункт 10 исходного описания (полный путь к папке) снят: браузер не раскрывает
  полный путь; строка «Папка: &lt;имя&gt;» в левой панели остаётся как в фиче 001.
- Краткие обозначения типов выбраны по образцу пользователя («num, bol, str,
  object, any итд») и приведены к единому виду: num, str, bool, arr, obj, any.
- «Whitespace» в описании пользователя — клавиша Пробел.
- Выделение и связывание выполняются мышью; управление только с клавиатуры не
  входит в эту фичу (кроме Пробела, Escape и прежних сочетаний отмены).
- Положение плавающих окон и открытая вкладка палитры живут только в течение
  сессии; по умолчанию левая панель — у левого края, палитра — по центру,
  окно свойств — рядом с выделенным нодом.
- Оформление (точные цвета, шрифты, отступы) берётся по образцу скриншотов
  пользователя: светлый фон в точку, чёрные рамки нодов, серый текст типа,
  синяя рамка выделения.
- Набор категорий палитры — существующие категории встроенных нодов плюс
  «Составные»; ноды «Вход»/«Выход» видны в палитре только внутри составного нода.
- Существующие e2e-сценарии фичи 001, которые соединяют порты на холсте,
  переписываются под новый способ связывания; проверяемое ими поведение
  (типы, циклы, пересчёт) не меняется.
- Язык интерфейса — английский; подписи панелей окна свойств — «Inputs» и «Outputs».
