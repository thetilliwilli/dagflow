# Research: Новый облик редактора графов

**Feature**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md) | **Date**: 2026-10-05

Каждое решение оформлено как Decision / Rationale / Alternatives considered.
Стек фичи 001 не меняется ([research 001, R1](../001-dag-workflow-editor/research.md)):
новых зависимостей нет.

## R1. Новые зависимости

**Decision**: не добавлять. Плавающие окна, перетаскивание параметров, вкладки
палитры и прямые линии делаются средствами React, React Flow 12 и CSS.

**Rationale**: принцип I и раздел «Ограничения» конституции. Плавающее окно с
перетаскиванием за заголовок — около 80 строк. Перетаскивание параметра между
окном и нодом — это указатель плюс `document.elementFromPoint`, тоже немного кода.
Прямая линия и подпись есть в React Flow (`getStraightPath`, `BaseEdge`,
`EdgeLabelRenderer`, `MarkerType.ArrowClosed`).

**Alternatives considered**: `react-rnd` / `react-draggable` для окон (лишняя
зависимость ради одной функции: изменение размера окон спека не требует);
`@dnd-kit/core` для связывания (рассчитан на сортировку и списки, а здесь цель —
нод React Flow под курсором с учётом масштаба; свой код короче).

## R2. Одна прямая линия на пару нодов

**Decision**: связи графа группируются в **пучки** чистой функцией
`bundleEdges(edges)`: один пучок на упорядоченную пару (источник, получатель).
В React Flow передаётся одно ребро на пучок (`id = bundle:<source>-><target>`,
`type: 'bundle'`). Компонент `BundleEdge` рисует прямую линию со стрелкой от края
прямоугольника источника к краю прямоугольника получателя («плавающие» концы):
точки на рамках считает чистая функция `borderPoint(rect, toward)`, размеры и
позиции нодов берутся из `useInternalNode`. Подпись — `EdgeLabelRenderer`, текст —
`bundleLabel(bundle, names, 5)`: строки «выход→вход», не больше 5 и строка «ещё N».

Обратного пучка (B → A при наличии A → B) быть не может: это цикл, движок его
запрещает. Поэтому пара нодов всегда даёт ровно одну линию (SC-004).

**Rationale**: FR-023, FR-024; группировка и геометрия — чистые функции с
unit-тестами (принцип II), компонент остаётся тонким.

**Alternatives considered**: встроенный тип `straight` — его концы привязаны к
портам-«ручкам» по бокам нода, а связь может идти в любую сторону (на скриншоте
линии идут и вниз, и вверх); отдельные рёбра на каждую связь с общей геометрией —
наложение подписей и щелчков, сложнее окно связей.

## R3. Ноды без портов-«ручек»

**Decision**: у карточки нода остаются две невидимые служебные «ручки» React Flow
(одна source, одна target) только для того, чтобы React Flow мог отрисовать
ребро-пучок. Соединять ими нельзя: `nodesConnectable={false}`, ручки скрыты
CSS и не принимают указатель.

**Rationale**: React Flow 12 не рисует ребро без ручек у нода (пишет ошибку в
консоль). Положение ручек не важно — `BundleEdge` считает концы сам (R2).

**Alternatives considered**: рисовать линии своим SVG-слоем поверх холста —
пришлось бы самим синхронизировать масштаб, панораму и выделение.

## R4. Выделение и состояние интерфейса

**Decision**: отдельный маленький стор интерфейса `src/store/ui.ts` (Zustand
vanilla, как основной стор): выделенные ноды, открытые плавающие окна и их
положения, порядок окон по z, вкладка палитры, открытое окно связей, состояние
связывания. Он живёт в памяти, не сохраняется и не попадает в историю отмены.
Переходы — чистые функции-редьюсеры в `src/store/ui-logic.ts` с unit-тестами.
Выделение хранится в сторе интерфейса: холст передаёт React Flow флаг `selected` из стора,
а изменения `select` из `onNodesChange` записывает обратно (уточнено на шаге implement:
с `onSelectionChange` React Flow перетирал бы выделение, заданное извне).

**Rationale**: property grid, карточки нодов, холст и палитра должны видеть одно и
то же выделение и режим связывания. В основной стор это класть нельзя: на его
изменения подписаны автосохранение и история. Состояние окон в спеке явно
сессионное (Key Entities → «Плавающее окно»).

**Alternatives considered**: React Context с `useReducer` в `Editor` — левая
панель и уведомления живут вне `Editor`, пришлось бы поднимать контекст до
`Workbench` и терять выборочные подписки; поле `ui` в основном сторе — лишние
срабатывания автосохранения.

## R5. Связывание: перетаскивание и режим привязки

**Decision**: одна машина состояний в сторе интерфейса:

```text
idle ──pointerdown на строке/маркере──▶ pressed
pressed ──сдвиг > 4 px──▶ dragging(from)          (перетаскивание, FR-018)
pressed ──pointerup без сдвига на маркере──▶ picking(from)   (режим привязки, FR-018a)
dragging/picking ──курсор над нодом B──▶ peek = B (временное окно свойств B)
dragging ──pointerup на доступной строке B──▶ connect → idle
picking ──щелчок по доступной строке B──▶ connect → idle
dragging ──pointerup не на строке / Escape──▶ idle
picking ──Escape / щелчок по пустому холсту / повторный щелчок по маркеру──▶ idle
dragging/picking ──щелчок/отпускание на недоступной строке──▶ сообщение;
                   dragging → idle, picking остаётся
```

Цель под курсором ищется `document.elementFromPoint` → ближайший
`.react-flow__node[data-id]` или окно `[data-peek-node]`. Временное окно остаётся
открытым, пока курсор над нодом B или над самим окном (с запасом 24 px, чтобы окно не
пропадало в зазоре между ними), переключается, когда курсор оказывается над другим
нодом, и закрывается, когда курсор ушёл дальше — иначе окно нода, над которым курсор
прошёл, загораживало бы соседние ноды (выяснено на шаге implement). Окно стоит над
остальными окнами (z-index 100).

Выделение на холсте читается из стора интерфейса в момент изменения и ограничивается
нодами графа текущей вкладки: React Flow прежней вкладки может прислать изменение
выделения уже после её закрытия (выяснено на шаге implement). Пока идёт связывание, у React Flow выключены
перетаскивание и выделение нодов (`nodesDraggable`, `elementsSelectable` = false),
поэтому щелчок по B не снимает выделение с A, а холст не сдвигается.

Доступность строк считает чистая функция движка
`linkCandidates(graph, from, targetNodeId, registry)`: для каждого порта нода B —
`{ok: true, replaces?}` или `Rejection`. Она переиспользует `canConnect` и
добавляет отказ `same-side` (вход со входом, выход с выходом). При перетаскивании
входа связь строится в обратную сторону: `source` = выход B, `target` = вход A.

**Rationale**: один источник правды для обоих способов связывания; все правила
(типы, цикл, тот же нод, сторона) тестируются без UI. Указатель, а не HTML5 drag
and drop: у HTML5 DnD нет `pointermove` во время перетаскивания, метка за курсором
— только картинка браузера, а отличить щелчок по маркеру от начала перетаскивания
сложнее.

**Alternatives considered**: HTML5 drag and drop (как у палитры) — нет контроля
над меткой и наведением на ноды React Flow; встроенное соединение React Flow —
требует видимых ручек на карточке, что противоречит FR-007.

## R6. Плавающие окна

**Decision**: общий компонент `FloatingWindow` (заголовок, кнопка закрытия,
перетаскивание за заголовок указателем, `position: absolute` поверх холста).
Положение ограничивает чистая функция `clampToViewport(rect, viewport)`; при
изменении размера окна браузера окна заново ограничиваются. Порядок по z — список
`windowOrder` в сторе интерфейса: открытие или щелчок по окну поднимает его наверх.
Окна не перехватывают события за своими границами (контейнер слоя —
`pointer-events: none`, само окно — `auto`), поэтому холст работает (FR-002).

Положения по умолчанию: левая панель — у левого края под кнопкой меню, палитра —
горизонтальной полосой внизу по центру (между кнопками масштаба и мини-картой;
уточнение пользователя после US1), окно свойств — у правого края под полосой вкладок (Clarifications),
окно связей — рядом с точкой щелчка, временное окно — рядом с нодом B со стороны,
где больше места.

**Escape** обрабатывает один глобальный обработчик по приоритету: связывание →
переименование (локально в поле ввода) → верхнее открытое окно; для окна свойств
«закрыть» означает снять выделение (US3, сценарий 6).

**Rationale**: FR-001 – FR-003; логика положения и порядка тестируется unit-тестами.

**Alternatives considered**: `<dialog>` — модальный по умолчанию и с собственной
логикой фокуса и Escape, а окна должны быть неблокирующими.

## R7. Клавиша Пробел

**Decision**: глобальный обработчик `keydown` (рядом с `useShortcuts`) переключает
палитру по `Space`, если фокус не в `input`, `textarea`, `select`,
`contenteditable` и не идёт связывание. В React Flow отключается
панорамирование по Пробелу: `panActivationKeyCode={null}`.

**Rationale**: FR-005, US1 сценарий 8. В React Flow по умолчанию Пробел включает
перетаскивание холста — без отключения палитра и панорама конфликтовали бы.

**Alternatives considered**: другая клавиша — пользователь явно выбрал Пробел.

## R8. Имя экземпляра нода

**Decision**: **обязательное** поле `name: string` у `NodeInstance` (решение
пользователя на шаге plan). Имя задаётся всегда:
- `addNode` ставит `name = def.title`;
- `collapse` ставит экземпляру имя составного нода;
- `expand` сохраняет имена внутренних нодов (копирование уже это делает);
- `duplicateWorkflow`, импорт и вставка копируют имена как есть.

Действие `renameNode(nodeId, name)` нормализует имя функцией
`normalizeNodeName(name)`: обрезает пробелы; пустое имя → отказ `empty-name`,
длиннее 100 символов → отказ `name-too-long`. Имя, совпадающее с названием типа,
хранится как обычное. Переименование — шаг истории с ключом `name:<id>`.
Отображается всегда `node.name`.

Переименование составного нода в палитре **не меняет** имена его экземпляров:
имя принадлежит экземпляру. Новые экземпляры получают новое имя.

Сообщения движка, которые называют другой нод (например, «Нод «…» выше по графу
ожидает входов»), используют имя экземпляра, а не название типа: на графе с
несколькими «Числами» иначе непонятно, о каком ноде речь.

**Формат файлов.** Поле `name` обязательно в схеме нода; версия формата остаётся
1 ([contracts/file-formats.md](./contracts/file-formats.md)). Совместимости со
старыми файлами нет (Clarifications спеки): файл без имён нодов не проходит
проверку схемы и обрабатывается как любой некорректный файл — понятная ошибка при
загрузке из файла, «недоступен» с причиной в рабочей папке. Нового кода для этого
не нужно: работают механизмы фичи 001.

**Rationale**: имя — часть нода, а не вычисляемое значение, и одинаково
присутствует в памяти, в файлах и в выгрузке. Отказ от совместимости — решение
пользователя: миграции форматов — отдельная фича, полурешения здесь не нужны
(принцип I). Принцип III соблюдается: некорректный файл даёт понятную ошибку и не
мешает остальным данным.

**Alternatives considered** (отклонены пользователем):
- необязательное поле, отсутствие которого означает «имя по типу»;
- мягкое чтение старых файлов с заполнением имени по типу;
- версия формата 2 с миграцией файлов версии 1.

## R9. Размер карточки нода

**Decision**: только CSS. Карточка — `width: fit-content; min-width: 20ch;
max-width: 40ch;` фиксированная высота `--node-height`, рассчитанная на строку
типа, 3 строки имени и строку проблемы; `border-radius: 0`. Имя —
`display: -webkit-box; -webkit-line-clamp: 3; overflow-wrap: anywhere`; тип и
текст проблемы — одна строка с `text-overflow: ellipsis`. Полный текст — в `title`.
Шрифт карточки — моноширинный, как на скриншотах (тогда `ch` точно равен символу).

Замечание с шага implement: при пределе имени в 100 символов и ширине 40 символов три
строки почти всегда вмещают имя целиком, поэтому многоточие срабатывает редко (длинные
слова, широкие символы). e2e проверяет, что имя занимает не больше 3 строк и полное имя
есть во всплывающей подсказке. На карточке значок состояния — без подписи (подпись не
помещается рядом с типом при ширине 20 символов): она в подсказке и в разметке
(`.node-status__label`).

**Rationale**: FR-007, FR-007a; `-webkit-line-clamp` поддерживают Chromium
и Firefox. Проверка — компонентный тест на классы и e2e на размеры
(ширина в пределах 20–40 символов, высота одинакова).

**Alternatives considered**: измерять текст в JS и резать вручную — сложнее и
медленнее на 100 нодах.

## R10. Подписи при уменьшении холста

**Decision**: `BundleEdge` читает масштаб через `useStore((s) => s.transform[2])`
и не рендерит подпись при масштабе `< 0.5` (константа `LABEL_MIN_ZOOM`). Линия и
стрелка остаются, щелчок по линии работает (`interactionWidth` линии — 12 px).

Минимальный масштаб холста — 0,1 (`minZoom`): по умолчанию в React Flow он 0,5, и
подписи никогда бы не скрывались (выяснено на шаге implement).

**Rationale**: FR-024 (Clarifications); меньше DOM на уменьшенном большом графе.

## R11. Палитра

**Decision**: палитра становится плавающим окном с вкладками: по одной на
категорию (`categories` движка в их порядке), плюс «Мои составные ноды» и, только
во вкладке составного нода, «Интерфейс составного нода». Последняя выбранная
вкладка запоминается в сторе интерфейса на сессию. Добавление: перетаскивание на
холст (как сейчас) или **одиночный** щелчок — в центр видимой области (раньше —
двойной щелчок). Палитра после добавления остаётся открытой.

Палитра — **горизонтальная полоса внизу по центру** (уточнение пользователя после
US1: окно по центру закрывало ноды, добавленные щелчком): ширина — от кнопок масштаба
до мини-карты (`calc(100vw - 2 × 240px)`, не уже 480 px), высота содержимого —
не больше 30% окна; ноды — плитками в сетке `auto-fill` по 200 px. «Центр видимой
области» для щелчка — центр части холста над палитрой.

**Rationale**: FR-005, FR-006.

## R12. Каркас рабочей области

**Decision**: `Workbench` — полоса сверху (кнопка меню ☰ + `TabBar`) и холст на
остальную высоту. Боковая панель превращается в `SidebarWindow` (плавающее окно с
`StorageIndicator`, `WorkflowList`, `ExportImport`). `FolderBanner` и
`Notifications` — уведомления поверх холста. Предложения о хранилище
(`FolderBanner`) — вверху левой панели, а на кнопке меню горит точка, пока такое
сообщение есть (FR-006a; уточнение пользователя после US3 — плашку поверх холста
закрывало окно свойств, а раньше она перехватывала броски нодов). Чтобы панель
можно было закрывать без потери прогресса, этап подсказки (подсказка → напоминание →
скрыто) хранится в сторе интерфейса, а не в состоянии компонента. Какое сообщение
показывать, решает чистая функция `storageNotice(state, stage)` — её же использует
кнопка меню для точки. Уведомления и модальные диалоги — над слоем окон (z-index 30 и 40). Панель
инструментов холста (отменить, повторить, свернуть в составной нод) остаётся в
левом верхнем углу холста. Мини-карта и кнопки масштаба остаются.

**Rationale**: FR-001, FR-004, FR-006a; SC-001.

## R13. Тесты и перевод существующих тестов

**Decision**:
- Unit (Vitest, node): `bundleEdges`, `bundleLabel`, `borderPoint`,
  `clampToViewport`, редьюсеры стора интерфейса (окна, Escape, машина связывания),
  `linkCandidates` и отказ `same-side`, `renameNode`/`normalizeNodeName`, схема с
  обязательным `name` (файл без имён отклоняется).
- Компонентные (jsdom): `FlowNode` (тип, имя, состояние, текст проблемы, нет
  ручек), `PropertyGrid` (строки, маркеры, сокращения типов, ручной ввод, источник
  подключённого входа, действия составного и IO-нода, затенение без изменения
  состава строк), `Palette` (вкладки, щелчок добавляет), `FloatingWindow`,
  `EdgeListWindow` (удаление крестиком).
- E2E (Playwright): по сценариям US1–US5 спеки 002. Хелперы `tests/e2e/helpers.ts`:
  `addNode` — через палитру (Пробел + вкладка), `connect` — перетаскивание строки
  из окна свойств на нод и бросок на строку временного окна; новые `linkByClick`,
  `setInput`, `openSidebar`. Существующие e2e фичи 001 переводятся на новые
  хелперы; проверяемое ими поведение не меняется.
- Перф: SC-005 — время появления окна свойств и временного окна на графе из
  100 нодов; SC-008 — существующие замеры SC-002/SC-003 фичи 001.
  Уточнение с шага implement: на карточке больше нет значений, а окно свойств одно,
  поэтому SC-003 меряется так — окно свойств открыто на последнем ноде, значение
  первого меняется отменой/повтором (Ctrl+Z / Ctrl+Shift+Z). Появление окон (SC-005)
  меряется внутри страницы: от последнего события указателя до появления окна
  (MutationObserver). Прежний перф-тест падал ещё до фичи 002: щелчок по заголовку
  нода на графе из 100 нодов не дожидался «стабильности» элемента.

**Rationale**: принцип II — у каждого acceptance-сценария есть тест; логика
вынесена из компонентов.
