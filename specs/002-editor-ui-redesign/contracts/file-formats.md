# Contract: изменения форматов файлов

Дополняет [file-formats.md фичи 001](../../001-dag-workflow-editor/contracts/file-formats.md).
Версия формата не меняется: `version: 1`. Совместимости с файлами, сохранёнными до
фичи 002, нет (Clarifications спеки, research R8).

## Нод в графе

В объект нода (`graph.nodes[]` в `*.workflow.json`, `*.composite.json` и в файле
выгрузки `.dagflow.json`) добавляется обязательное поле `name`:

```json
{ "id": "n2", "type": "builtin:add", "name": "Итого", "position": { "x": 200, "y": 0 }, "values": {} }
```

| Поле | Тип | Правила |
|---|---|---|
| `name` | string, **обязательное** | после `trim` 1–100 символов; при создании нода равно названию типа |

## Файлы без имён нодов

- Нод без `name`, с пустым `name` или длиннее 100 символов — ошибка схемы с путём
  к полю, как у любого некорректного файла:
  - загрузка из файла — понятное сообщение, список workflow не меняется
    (FR-030 фичи 001);
  - рабочая папка / OPFS — workflow или составной нод помечается недоступным с
    причиной (edge case фичи 001 о повреждённом файле), остальные открываются.
- Миграций и заполнения имён при чтении нет: это отдельная будущая фича.

## Сериализация

- Порядок ключей нода: `id`, `type`, `name`, `position`, `values`, `ports`.
- Имена нодов участвуют в «содержательном равенстве» определений составных нодов
  при импорте (FR-029a фичи 001): определения, отличающиеся только именами
  внутренних нодов, считаются разными.
