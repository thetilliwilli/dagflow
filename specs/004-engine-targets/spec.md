# Feature Specification: Выполнение workflow на выбранном engine

**Feature Branch**: `004-engine-targets`

**Created**: 2026-10-07

**Status**: Draft

**Input**: User description: "Выполнение workflow на выбранном engine: в том же окне браузера, в фоновом потоке браузера или на удалённом сервере выполнения. Пользователь хочет вычислять workflow не только в окне редактора, но и в фоне (тяжёлые графы не подвешивают интерфейс) и на собственном сервере. Engine (правила графа и вычисление) один и тот же везде и в перспективе встраивается в любую среду выполнения JavaScript; в этой фиче поддерживаются браузер (то же окно и фоновый поток) и серверные среды Node, Bun, Deno. Выбор цели — плоский список в левой панели; короткий адрес сервера, схему подключения подбирает приложение, порт не додумывается; пробное переключение; индикатор подключения всегда виден; данные только у пользователя, сервер держит граф в памяти; при обрыве редактирование не блокируется, значения приглушены, повторные попытки с растущей паузой; несовпадение версий — понятное сообщение; ошибки обмена — понятные сообщения и самовосстановление; падение фонового потока — перезапуск; сервер запускается командой, по умолчанию слушает только локальный адрес, доступ осознанно открыт для любого источника; одинаковые результаты во всех средах; скорость SC-003 сохраняется."

## Контекст

- Поправки к конституции 2.0.0 и 2.1.0 разрешили сервер выполнения и закрепили правила
  для engine: один пакет для всех сред, ядро без ввода-вывода, проверка собранного
  бандла в каждой поддерживаемой среде.
- Сейчас workflow вычисляется в окне редактора. Эта фича добавляет ещё две цели
  вычисления: фоновый поток браузера и сервер выполнения. Правка графа, проверки связей,
  палитра, хранение и выгрузка (фичи 001–003) не меняются и работают без сервера.
- Материалы обсуждения архитектуры (протокол, переподключение, интерфейс) —
  `ignore/artefacts/` (вне репозитория); технические решения оттуда переносятся в plan.

## Clarifications

### Session 2026-10-07

- Q: Что считать совместимостью редактора и цели при подключении? → A: Сверяется только
  версия протокола обмена (целое число; поднимается при несовместимом изменении формата
  сообщений, формы графа и состояний нодов или правил совместимости типов портов).
  Версия engine только показывается; при различии видны обе. Палитра и проверки связей
  — по встроенному каталогу редактора. Каталог нодов от цели — отдельная фича
  (`specs/BACKLOG.md`); скачивание кода engine с сервера отклонено (чужой код получил бы
  доступ к данным и рабочей папке пользователя).
- Q: В каком виде пользователь получает сервер, чтобы запустить его на другой машине?
  → A: Оба варианта: запуск из папки проекта (для разработки) и один собранный
  самодостаточный файл сервера, который без установки зависимостей запускается любой
  из сред Node, Bun, Deno; автоматические проверки в трёх средах идут на этом файле.
- Q: Что сервер печатает в консоль во время работы? → A: По строке на каждое
  подключение и отключение (адрес клиента, число подключений) и на каждую ошибку обмена
  (код); с флагом `--verbose` — ещё строка на каждое сообщение обмена (тип, вкладка,
  размер). Содержимое workflow и значения нодов не печатаются никогда.
- Q: Если редактор открыт в двух окнах одного браузера и в одном меняют цель
  вычисления, что происходит во втором? → A: Окна независимы: второе окно продолжает
  работать со своей целью и своим списком; сохраняется последний выбор, его берут новые
  окна и перезагрузка.
- Q: «Use local engine» — постоянная смена цели или временная замена, пока сервер не
  вернётся? → A: Постоянная: то же, что щелчок по строке «This tab · Local» — цель
  «Local» выбирается и сохраняется, попытки подключиться к прежней цели прекращаются,
  сервер остаётся в списке.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Вычисление на своём сервере (Priority: P1)

Пользователь запускает сервер выполнения на своём компьютере одной командой, открывает
в левой панели раздел «Engine», вводит короткий адрес `localhost:8080` и нажимает
«Connect». После подключения все открытые вкладки вычисляются на сервере: значения в
нодах те же, что при вычислении в окне, и обновляются при каждой правке. В верхней
панели видно, где идёт вычисление: «● Server · localhost:8080».

**Why this priority**: это главная цель фичи — вынести вычисление из окна редактора на
сервер. Без неё остальные истории теряют смысл.

**Independent Test**: запустить сервер на свободном порту, подключиться по адресу,
собрать граф «2 + 3 → Show», поменять вход — значения пересчитываются, а значения и
сообщения нодов совпадают с вычислением в окне.

**Acceptance Scenarios**:

1. **Given** сервер запущен на порту 8080, **When** пользователь вводит `localhost:8080`
   и нажимает «Connect», **Then** после подтверждения сервера выбранной становится
   строка «localhost:8080 · Server», индикатор показывает «● Server · localhost:8080»
   и версию engine сервера,
   а ноды всех открытых вкладок получают значения, вычисленные сервером.
2. **Given** редактор подключён к серверу, **When** пользователь меняет значение входа,
   добавляет нод или связь, **Then** зависимые ноды сначала показывают «computing», а
   затем новые значения от сервера.
3. **Given** редактор подключён к серверу, **When** в графе есть ошибка нода (например,
   деление на ноль) или незаполненный обязательный вход, **Then** нод показывает то же
   состояние и тот же текст, что при вычислении в окне.
4. **Given** редактор подключён к серверу, **When** пользователь правит составной нод,
   **Then** пересчитываются экземпляры этого нода во всех открытых вкладках.
5. **Given** редактор подключён к серверу, **When** пользователь открывает или закрывает
   вкладку, **Then** новая вкладка вычисляется на сервере, а закрытая перестаёт
   занимать память сервера.
6. **Given** по адресу ничего не запущено, **When** пользователь нажимает «Connect»,
   **Then** у поля появляется ошибка «Could not connect to localhost:8081. Check that
   the server is running and the address is correct.», а вычисление продолжается на
   прежней цели.
7. **Given** пользователь ввёл адрес без порта (`domain.com`), **When** он подключается,
   **Then** приложение не подставляет свой порт: используется адрес как он введён.
8. **Given** по введённому адресу работает другой сервис (не engine), **When**
   пользователь нажимает «Connect», **Then** подключение считается неудачным, у поля —
   понятная ошибка, прежняя цель остаётся.

### User Story 2 - Вычисление в фоновом потоке (Priority: P2)

Пользователь выбирает в разделе «Engine» строку «This browser · Worker». Вычисление
переходит в фоновый поток браузера: интерфейс остаётся отзывчивым даже на тяжёлых
графах, а значения в нодах те же.

**Why this priority**: даёт пользу без сервера (отзывчивый интерфейс) и проверяет, что
один и тот же engine работает вне окна редактора.

**Independent Test**: выбрать «Worker», собрать граф, поменять вход — значения
пересчитываются и совпадают с вычислением в окне; индикатор показывает «● Worker».

**Acceptance Scenarios**:

1. **Given** выбрано вычисление в окне, **When** пользователь выбирает строку «Worker»,
   **Then** после подтверждения фонового потока выбранной становится она, индикатор
   показывает «● Worker», ноды всех вкладок пересчитываются в фоне с теми же значениями.
2. **Given** выбран фоновый поток, **When** он аварийно завершается, **Then** редактор
   перезапускает его, повторно передаёт открытые вкладки и показывает уведомление
   «The engine restarted after a failure.»
3. **Given** фоновый поток упал третий раз за минуту, **When** это происходит, **Then**
   редактор больше не перезапускает его, индикатор показывает проблему и предлагает
   «Use local engine» (вычисление в окне).
4. **Given** выбран фоновый поток, **When** пользователь выбирает строку «This tab ·
   Local», **Then** вычисление возвращается в окно редактора без потери значений.

### User Story 3 - Работа без связи с сервером и восстановление (Priority: P2)

Сервер останавливается или пропадает сеть. Пользователь продолжает редактировать
граф: ничего не блокируется, ноды показывают последние известные значения приглушённо.
Редактор сам пытается переподключиться; как только сервер снова доступен, значения
пересчитываются.

**Why this priority**: обрыв связи с сервером неизбежен; работа пользователя не должна
от него страдать (конституция, принцип III).

**Independent Test**: подключиться к серверу, остановить его, поменять граф, снова
запустить сервер — индикатор проходит «Offline» → «Server», значения пересчитаны с
учётом правок, сделанных без связи.

**Acceptance Scenarios**:

1. **Given** редактор подключён к серверу, **When** сервер останавливается, **Then**
   индикатор показывает «◌ Offline — retrying in N s» с кнопкой «Retry now», а ноды
   показывают последние известные значения приглушённо; в окне «Properties» —
   пометка «Last known value — engine offline».
2. **Given** связи нет, **When** пользователь добавляет ноды, связи, правит значения,
   переключает вкладки, **Then** всё работает как обычно: проверки связей, палитра,
   история отмены и сохранение не зависят от сервера; новые и изменённые ноды ждут
   пересчёта.
3. **Given** связи нет, **When** редактор повторяет попытки, **Then** пауза между
   попытками растёт и не превышает 10 с; попытки продолжаются, пока открыт редактор.
4. **Given** связи нет, **When** пользователь нажимает «Retry now», **Then** попытка
   выполняется сразу.
5. **Given** связи нет и сервер снова запущен, **When** очередная попытка удаётся,
   **Then** редактор передаёт серверу все открытые вкладки в текущем виде (с правками,
   сделанными без связи), значения пересчитываются, приглушение снимается.
6. **Given** сервер перезапущен (свежий, без данных), **When** редактор подключается,
   **Then** результат тот же, что в сценарии 5: сервер ничего не помнил, и это не
   важно — граф у пользователя.
7. **Given** при открытии редактора сохранённой целью был сервер и он недоступен,
   **When** редактор загружается, **Then** редактор полностью работает, индикатор
   показывает «Offline» и предлагает «Use local engine».
8. **Given** связи с сервером нет, **When** пользователь нажимает «Use local engine»,
   **Then** выбрана строка «This tab · Local», значения пересчитываются в окне, попытки
   подключения к серверу прекращаются, сервер остаётся в списке; после перезагрузки
   выбрана «Local».

### User Story 4 - Список целей и запоминание выбора (Priority: P2)

В разделе «Engine» левой панели — один плоский список целей. Каждая строка — индикатор
выбранной цели, адрес и тип: «This tab · Local», «This browser · Worker» и до пяти
последних серверов «localhost:8080 · Server». Щелчок по строке подключает к цели.
Выбор и список сохраняются между сессиями. Индикатор в верхней панели всегда показывает
текущую цель и открывает этот раздел по щелчку.

**Why this priority**: делает работу с несколькими целями удобной, но вычисление на
сервере (US1) возможно и без списка недавних.

**Independent Test**: подключиться к двум серверам по очереди, перезагрузить
страницу — оба в списке, выбран последний; убрать один «×» — он пропал; щелчок по
строке «Local» — вычисление в окне.

**Acceptance Scenarios**:

1. **Given** пользователь впервые открывает редактор, **When** он смотрит на раздел
   «Engine», **Then** в списке две строки — «This tab · Local» (выбрана) и «This
   browser · Worker», — а индикатор в верхней панели показывает «● Local».
2. **Given** пользователь успешно подключился к новому серверу, **When** он смотрит на
   список, **Then** сервер появился в нём, выбран и стоит первым среди серверов.
3. **Given** в списке уже пять серверов, **When** пользователь подключается к шестому,
   **Then** из списка уходит сервер, использованный давнее всех.
4. **Given** в списке есть сервер, **When** пользователь щёлкает по его строке,
   **Then** выполняется пробное подключение (как «Connect» в US1).
5. **Given** в списке есть невыбранный сервер, **When** пользователь нажимает «×» у
   него, **Then** строка исчезает. У выбранной строки и у локальных строк «×» нет.
6. **Given** пользователь выбрал цель, **When** он перезагружает страницу, **Then**
   редактор подключается к той же цели, список серверов сохранён.
7. **Given** выбрана цель, **When** пользователь щёлкает по индикатору в верхней
   панели, **Then** открывается левая панель с разделом «Engine».
8. **Given** пользователь ввёл пустой адрес или адрес с недопустимыми символами,
   **When** он нажимает «Connect», **Then** у поля — ошибка «Enter a server address,
   for example localhost:8080.», подключение не начинается.
9. **Given** выбран сервер, **When** пользователь выгружает workflow в файл, **Then**
   в файле нет сведений о цели вычисления.
10. **Given** редактор открыт в двух окнах браузера с целью «Local», **When** в первом
    окне пользователь подключается к серверу, **Then** второе окно продолжает
    вычислять в окне и его список не меняется; после перезагрузки второго окна
    выбран сервер.

### User Story 5 - Запуск сервера в Node, Bun или Deno (Priority: P2)

Пользователь запускает сервер выполнения той средой, которая у него установлена:
Node, Bun или Deno. Сервер сообщает адрес, на котором ждёт подключений; понятно
объясняет проблемы запуска; по умолчанию доступен только с этого компьютера.

**Why this priority**: кроссплатформенность engine — одна из целей фичи; без запуска
сервера US1 не проверить.

**Independent Test**: запустить сервер в каждой из трёх сред, подключиться из
редактора, открыть один и тот же workflow — значения и сообщения нодов одинаковые.

**Acceptance Scenarios**:

1. **Given** установлена одна из сред Node, Bun, Deno, **When** пользователь запускает
   сервер с портом 8080, **Then** сервер печатает, где ждёт подключений (например,
   «DAG Flow engine 0.2.0 is listening on localhost:8080»), и принимает подключения
   только с этого компьютера.
2. **Given** порт занят, **When** пользователь запускает сервер, **Then** сервер
   печатает «Port 8080 is already in use. Start the server with another port.» и
   завершается без трассировки.
3. **Given** пользователь запускает сервер с адресом прослушивания для всей сети,
   **When** сервер стартует, **Then** он предупреждает: «The engine has no
   authentication. Anyone who can reach this address can run workflows on it.»
4. **Given** один и тот же workflow, **When** он вычисляется в окне, в фоновом потоке
   и на сервере под Node, Bun и Deno, **Then** состояния, значения и сообщения всех
   нодов совпадают.
5. **Given** веб-страница с любого источника, **When** она подключается к серверу,
   **Then** сервер её принимает (осознанное решение; защита — фича «Защита сервера
   выполнения» в `specs/BACKLOG.md`).
6. **Given** к серверу подключены два окна редактора, **When** каждое открывает свои
   вкладки, **Then** вкладки одного окна не видны и не влияют на вкладки другого.
7. **Given** сервер запущен, **When** редактор подключается, отключается или
   присылает отклонённое сообщение, **Then** сервер печатает об этом по одной строке
   (адрес клиента, число подключений, код ошибки); с `--verbose` — строку на каждое
   сообщение обмена; ни в одном режиме в выводе нет содержимого workflow и значений.
8. **Given** собранный файл сервера скопирован в пустую папку на машине, где есть
   только одна из сред Node, Bun, Deno (без копии проекта и установки зависимостей),
   **When** пользователь запускает его этой средой с портом 8080, **Then** сервер
   стартует и редактор подключается к нему.

### User Story 6 - Несовместимая версия и ошибки обмена (Priority: P3)

Редактор и сервер могут быть разных версий, а обмен — сбоить. Пользователь видит,
что произошло и что делать, а редактор сам восстанавливается там, где это возможно.

**Why this priority**: редкие ситуации, но без них ошибки были бы непонятными
(принцип IV).

**Independent Test**: запустить сервер с другой версией протокола и подключиться —
понятное сообщение и предложение перейти на вычисление в окне; запустить сервер с
другой версией engine и той же версией протокола — подключение работает, видны обе
версии; отправить слишком большой workflow — сообщение о лимите.

**Acceptance Scenarios**:

1. **Given** у сервера другая версия протокола, **When** пользователь подключается
   вручную, **Then** у поля — «The server uses a different protocol version (server 2,
   editor 1). Update the server or the editor.», прежняя цель остаётся.
2. **Given** сохранённая цель — сервер, и после его обновления версии протокола
   разошлись, **When** редактор подключается, **Then** индикатор показывает «Protocol
   version differs (server 2, editor 1)» с кнопкой «Use local engine»; автоматических
   повторов нет.
3. **Given** у сервера та же версия протокола, но другая версия engine, **When**
   редактор подключается, **Then** подключение работает, а индикатор и раздел «Engine»
   показывают обе версии: «engine 0.1.0 (editor 0.2.0)».
4. **Given** сервер не знает тип нода, который есть в редакторе, **When** вкладка с
   этим нодом вычисляется на сервере, **Then** этот нод показывает ошибку неизвестного
   типа, остальные ноды вычисляются как обычно.
5. **Given** workflow вкладки больше лимита (8 МБ), **When** редактор передаёт его
   серверу, **Then** на вкладке видно «This workflow is too large for the server
   (limit: 8 MB).», ноды вкладки приглушены; при следующей правке редактор пробует
   снова.
6. **Given** сервер отклонил запрос или не смог его обработать, **When** это
   происходит, **Then** пользователь видит уведомление «The engine could not process
   the workflow. Retrying.», а редактор повторно передаёт вкладку.
7. **Given** сервер забыл вкладку (например, после внутреннего сбоя), **When**
   редактор присылает правку, **Then** редактор молча передаёт вкладку заново, и
   значения пересчитываются.

---

### Edge Cases

- Сервер перезапустили во время пересчёта → обрыв, переподключение, полная передача
  вкладок (US3).
- Пользователь меняет цель, пока предыдущая без связи → пробное подключение к новой; при
  успехе попытки к старой прекращаются.
- Пользователь меняет цель, пока идёт пробное подключение к другой → прежняя попытка
  отменяется, выполняется новая.
- Пользователь вводит адрес со схемой (`http://…`, `ws://…`) → схема учитывается как
  подсказка (`http` — без шифрования, `https` — с шифрованием).
- Редактор открыт по защищённому адресу, сервер — не на этом компьютере и без
  шифрования → браузер запрещает такое подключение; ошибка объясняет, что серверу нужен
  защищённый адрес.
- Подключение к не-локальному адресу получилось только без шифрования → в индикаторе
  пометка «not encrypted».
- Вкладку закрыли без связи → при переподключении она не передаётся.
- Составной нод изменили без связи → после переподключения пересчитываются все
  вкладки, где он используется.
- Workflow с циклом или неизвестным типом нода (импорт старых данных) → сервер
  показывает те же состояния нодов, что вычисление в окне, и не падает.
- Два окна редактора с одним сервером → вкладки изолированы (US5 #6).
- Два окна редактора в одном браузере → цель у каждого своя, другое окно не
  переключается; сохраняется последний выбор (US4 #10).
- Сервер получает некорректное сообщение → отвечает ошибкой, соединение и остальные
  вкладки продолжают работать.
- Фоновый поток недоступен в браузере → строка «Worker» показывает ошибку при выборе,
  прежняя цель остаётся.

## Requirements *(mandatory)*

### Functional Requirements

**Цели и выбор**

- **FR-001**: Редактор ДОЛЖЕН вычислять workflow на одной из целей: в окне редактора
  («Local»), в фоновом потоке браузера («Worker») или на сервере выполнения («Server»).
  Цель одна для всех открытых вкладок.
- **FR-002**: Правка графа, проверки связей, палитра, история отмены, хранение,
  выгрузка и загрузка ДОЛЖНЫ работать одинаково при любой цели и без связи с ней.
- **FR-003**: В левой панели ДОЛЖЕН быть раздел «Engine» с одним плоским списком целей
  (без вложенности). Строка — индикатор выбранной цели, адрес и тип подключения.
  Строки «This tab · Local» и «This browser · Worker» есть всегда и не удаляются;
  серверов — до 5, последний использованный первым.
- **FR-004**: Под списком ДОЛЖНЫ быть поле адреса сервера и кнопка «Connect». Успешное
  подключение добавляет сервер в список (или поднимает его наверх) и делает выбранным;
  при переполнении уходит сервер, использованный давнее всех.
- **FR-005**: У невыбранного сервера в списке ДОЛЖНА быть кнопка «×», убирающая его из
  списка. У выбранной строки и у локальных строк её нет.
- **FR-006**: Цель по умолчанию — «Local». Выбранная цель и список серверов ДОЛЖНЫ
  сохраняться в браузере между сессиями и НЕ ДОЛЖНЫ попадать в файлы workflow и
  выгрузку. Открытые окна редактора в одном браузере независимы: смена цели или списка
  в одном окне НЕ ДОЛЖНА менять цель и список в других открытых окнах; сохраняется
  последнее изменение, его берут новые окна и перезагрузка.
- **FR-007**: Ручная смена цели (щелчок по строке или «Connect») ДОЛЖНА быть пробной:
  пока идёт попытка, вычисление продолжается на прежней цели; переключение — только
  после того, как цель подтвердила, что это engine с той же версией протокола. При неудаче —
  понятная ошибка у поля или строки, прежняя цель остаётся. Новая попытка отменяет
  незавершённую.

**Адрес сервера**

- **FR-008**: Пользователь ДОЛЖЕН вводить короткий адрес: хост, необязательный порт и
  необязательный путь (`localhost:8080`, `domain.com`, `domain.com/path`). Пустой или
  некорректный адрес — ошибка у поля без попытки подключения.
- **FR-009**: Способ подключения (с шифрованием или без) ДОЛЖЕН подбираться
  автоматически: для адресов этого компьютера сначала без шифрования, для остальных —
  сначала с шифрованием. Если пользователь указал схему, она учитывается. Найденный
  способ запоминается у адреса и пробуется первым при следующем подключении.
- **FR-010**: Порт ДОЛЖЕН использоваться ровно такой, как указал пользователь;
  редактор не подставляет свой порт. Неверный порт приводит к понятной ошибке
  подключения.
- **FR-011**: Подключение к не-локальному адресу без шифрования ДОЛЖНО быть видно в
  индикаторе («not encrypted»). Если браузер запрещает такое подключение (редактор
  открыт по защищённому адресу), ошибка ДОЛЖНА это объяснять.
- **FR-012**: Попытка ДОЛЖНА считаться успешной только после подтверждения от engine
  (не просто открытого соединения) и неудачной, если подтверждения нет за 3 с.

**Индикатор и состояние**

- **FR-013**: В верхней панели справа от вкладок ДОЛЖЕН всегда быть виден индикатор
  цели и состояния: «● Local», «● Worker», «● Server · `адрес`» с версией engine
  сервера (при отличии от редактора — обе версии), «Connecting…», «◌ Offline —
  retrying in N s» с кнопкой «Retry now», «Protocol version differs (server X,
  editor Y)» с кнопкой «Use local engine». Щелчок открывает раздел «Engine».
- **FR-014**: Индикатор выбранной строки в списке ДОЛЖЕН показывать то же состояние
  (подключено — зелёный, иначе — цвет состояния).

**Вычисление на цели**

- **FR-015**: После подключения редактор ДОЛЖЕН передать цели все открытые вкладки и
  составные ноды; при каждой правке — новую версию вкладки; при правке составного
  нода — новые определения составных нодов; при закрытии вкладки — сообщить об этом.
- **FR-016**: Цель ДОЛЖНА сообщать, какие ноды пересчитываются (они показывают
  «computing»), и затем их новые состояния. Несколько правок, пришедших до пересчёта,
  объединяются в один пересчёт.
- **FR-017**: Состояния, значения и сообщения нодов ДОЛЖНЫ совпадать при вычислении
  на любой цели и в любой поддерживаемой серверной среде.
- **FR-018**: Сервер НЕ ДОЛЖЕН сохранять данные пользователя: граф и состояния живут в
  его памяти, пока открыто подключение; после отключения память освобождается.
  Вкладки разных подключений изолированы друг от друга.

**Обрыв и восстановление**

- **FR-019**: При потере связи редактор ДОЛЖЕН показывать «Offline», сохранять у нодов
  последние известные значения в приглушённом виде с пометкой «Last known value —
  engine offline» в окне «Properties» и не блокировать редактирование.
- **FR-020**: Редактор ДОЛЖЕН автоматически повторять подключение к выбранной цели с
  растущей паузой (не более 10 с), пока открыт; «Retry now» выполняет попытку сразу;
  восстановление сети в браузере тоже запускает попытку.
- **FR-021**: После подключения (в том числе к перезапущенному серверу) редактор
  ДОЛЖЕН передать все открытые вкладки в текущем виде; полученные значения заменяют
  приглушённые.
- **FR-022**: Если при открытии редактора сохранённая цель недоступна, редактор
  ДОЛЖЕН полностью работать, показывать «Offline» и предлагать «Use local engine».
- **FR-022a**: «Use local engine» (FR-022, FR-023, FR-027) ДОЛЖНА действовать как
  выбор строки «This tab · Local»: цель «Local» выбирается сразу (без пробной попытки —
  она всегда доступна) и сохраняется, попытки подключиться к прежней цели
  прекращаются, сервер остаётся в списке и выбирается обратно щелчком по строке.

**Ошибки**

- **FR-023**: При подключении ДОЛЖНА сверяться только версия протокола обмена. При
  разных версиях протокола подключение ДОЛЖНО отклоняться с сообщением, в котором
  названы обе версии и что делать; автоматических повторов нет, есть «Use local
  engine». Разная версия engine при той же версии протокола НЕ ДОЛЖНА мешать
  подключению: обе версии показываются (FR-013).
- **FR-023a**: Палитра и проверки связей ДОЛЖНЫ работать по встроенному каталогу нодов
  редактора при любой цели. Нод, тип которого цель не знает, показывает ошибку
  неизвестного типа, не мешая остальным нодам.
- **FR-024**: Workflow вкладки больше 8 МБ ДОЛЖЕН отклоняться сервером; на вкладке —
  сообщение о лимите, ноды приглушены; при следующей правке — новая попытка.
- **FR-025**: Если цель отклонила запрос или не смогла его обработать, пользователь
  ДОЛЖЕН увидеть уведомление, а редактор — повторно передать вкладку. Если цель
  «забыла» вкладку, редактор ДОЛЖЕН передать её заново без уведомления.
- **FR-026**: Некорректное сообщение НЕ ДОЛЖНО разрывать подключение и влиять на другие
  вкладки (кроме несовпадения версий).
- **FR-027**: При аварийном завершении фонового потока редактор ДОЛЖЕН перезапустить
  его, передать вкладки заново и показать уведомление; после 3 падений за минуту —
  не перезапускать и предложить «Use local engine».
- **FR-028**: Все новые тексты для пользователя — на английском (фича 003), понятные:
  что случилось и что делать (принцип IV).

**Сервер**

- **FR-029**: Сервер выполнения ДОЛЖЕН запускаться командой в Node, Bun и Deno с
  указанием порта и адреса прослушивания; по умолчанию слушает только адрес этого
  компьютера.
- **FR-029a**: Сервер ДОЛЖЕН запускаться двумя способами: из папки проекта (для
  разработки) и как один собранный самодостаточный файл, которому не нужны копия
  проекта и установка зависимостей; один и тот же файл запускается в Node, Bun и Deno.
  Проверки в трёх средах (SC-001, US5) выполняются на этом собранном файле.
- **FR-030**: Сервер ДОЛЖЕН печатать понятные сообщения: где ждёт подключений, занятый
  порт, неверные параметры запуска — без трассировок; при прослушивании адреса для
  сети — предупреждение об отсутствии аутентификации.
- **FR-030a**: Во время работы сервер ДОЛЖЕН печатать по строке на каждое подключение и
  отключение (адрес клиента и число открытых подключений) и на каждую ошибку обмена (её
  код). С флагом `--verbose` — дополнительно строку на каждое сообщение обмена в обе
  стороны (тип, вкладка, размер). Содержимое workflow, составных нодов и значения нодов
  в вывод сервера НЕ ДОЛЖНЫ попадать ни в каком режиме.
- **FR-031**: Сервер ДОЛЖЕН принимать подключения с любых веб-страниц (любого
  источника) и разрешать их запросы. Это осознанное решение; защита — отдельная фича
  (`specs/BACKLOG.md`, «Защита сервера выполнения»).

### Связь с фичами 001–003

- FR и состояния нодов фичи 001 не меняются; добавляется только приглушённый вид
  «последнее известное значение» при отсутствии связи (FR-019) — это не новое
  состояние нода.
- SC-003 фичи 001 распространяется на цели «Local» и «Worker» (SC-002 этой фичи).
- Хранение, автосохранение и выгрузка (001, 002) не зависят от цели.

### Key Entities

- **Цель вычисления**: тип (Local, Worker, Server) и для сервера — адрес в том виде,
  как ввёл пользователь, и найденный способ подключения (с шифрованием или без).
- **Список целей**: две постоянные локальные цели + до 5 серверов в порядке последнего
  использования; выбранная цель. Хранится в браузере, не в workflow.
- **Состояние подключения**: подключение, подключено (версия engine цели), нет связи
  (номер попытки, время следующей), другая версия протокола (версии сторон), сбой
  фонового потока.
- **Версия протокола**: целое число, общее для редактора и цели; поднимается при
  несовместимом изменении обмена. **Версия engine** — номер для показа.
- **Копия вкладки на цели**: граф вкладки и определения составных нодов в памяти цели;
  производная от данных пользователя, может быть потеряна без последствий.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Для набора эталонных workflow (все встроенные ноды, составные ноды,
  ошибки, ожидание входов) состояния, значения и сообщения всех нодов совпадают в 100%
  случаев при вычислении в окне, в фоновом потоке и на сервере под Node, Bun и Deno.
- **SC-002**: На графе из 100 простых нодов изменение входа отражается во всех
  зависимых нодах менее чем за 0,2 с при цели «Local» и «Worker» и менее чем за 0,5 с
  при сервере на том же компьютере.
- **SC-003**: После остановки сервера индикатор показывает «Offline» не позже чем
  через 2 с; после повторного запуска сервера значения пересчитываются не позже чем
  через 15 с без действий пользователя.
- **SC-004**: Во время отсутствия связи 100% действий редактирования (добавить нод,
  связь, правка значения, отмена, переключение вкладок) выполняются так же, как при
  связи, и ни одна правка не теряется после восстановления.
- **SC-005**: Пользователь, у которого запущен сервер, подключает к нему редактор менее
  чем за 30 с, вводя только короткий адрес.
- **SC-006**: Ни одна ошибка подключения или обмена не показывает пользователю сырые
  исключения; у каждой ошибки из сценариев US1, US5, US6 есть текст, проверенный тестом.
- **SC-007**: Сервер не создаёт файлов с данными пользователя: после работы с ним на
  диске сервера нет workflow и состояний.

## Assumptions

- Версию протокола поднимают вручную при несовместимом изменении обмена: сообщений,
  формы графа и состояний нодов, правил совместимости типов портов. Новые ноды,
  исправления вычислений и тексты её не меняют.
- В режиме «Server» значения считает только сервер; сервер другой версии engine даёт
  результаты своей версии — это видно по версии в индикаторе.
- «Адрес этого компьютера» — `localhost`, имена вида `*.localhost`, `127.0.0.1`, `[::1]`.
- Убрать из списка выбранный сервер нельзя: сначала нужно выбрать другую цель.
- Лимит 8 МБ относится к одной вкладке вместе с определениями составных нодов.
- Обнаружение обрыва при «тихой» потере сети (без закрытия соединения) может занимать
  больше 2 с; SC-003 относится к остановке сервера.
- Firefox поддерживает фоновый поток так же, как Chromium; Safari проверяется вручную
  (как в фичах 001–003).
- Сервер запускается пользователем вручную; собранный файл пользователь копирует сам.
  Автозапуск, установка как службы и публикация пакета в реестр — вне рамок.

### Вне рамок

- Защита сервера (аутентификация, проверка источника) — `specs/BACKLOG.md`.
- Многопользовательский режим, общие документы и хранение данных на сервере.
- Ноды с эффектами (сеть, файлы, время, случайность) и асинхронные ноды; возможности,
  передаваемые хостом.
- Просмотр состояний внутренних нодов составного нода с цели.
- Каталог нодов от цели (палитра и проверки по нодам сервера) — `specs/BACKLOG.md`.
- Загрузка кода engine с сервера в редактор (отклонено: чужой код получил бы доступ к
  данным и рабочей папке пользователя).
- Другие среды выполнения (njs, QuickJS, Office Add-ins, serverless) и сборки под них.
