# Research: Английский интерфейс и имена без ограничений длины

**Feature**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md) | **Date**: 2026-10-06

Каждое решение оформлено как Decision / Rationale / Alternatives considered.
Стек фич 001 и 002 не меняется; новых зависимостей нет.

## R1. Как переводить: константы, без локализации

**Decision**: строки остаются константами в тех же модулях, но становятся английскими.
Никаких ключей, словарей и библиотеки локализации. Точные формулировки —
[contracts/ui-texts.md](./contracts/ui-texts.md).

**Rationale**: язык один (FR-006, принцип I). Константы без ключей проще читать и
проверять тестами, чем словарь.

**Alternatives considered**: `i18next`/`react-intl` с русским и английским — локализация
не требуется спекой, новая зависимость (принцип I); словарь `t('key')` без библиотеки —
лишний слой ради одного языка.

## R2. Где живут тексты

**Decision**: правило `CLAUDE.md` «тексты для пользователя — только в
`src/ui/messages.ts` и `src/engine/errors.ts`» выполняется полностью:

| Где сейчас | Что | Куда |
|---|---|---|
| `src/engine/errors.ts` | отказы, названия типов, «внутренняя ошибка» | остаются, переводятся |
| `src/engine/builtins/*` | названия, описания, категории встроенных нодов, тексты `NodeError` | названия и описания остаются в определениях нодов (это данные каталога, как в 001); тексты ошибок нодов — в `errors.ts` (`nodeErrors`) |
| `src/engine/values.ts` | `describeKind`, `formatCompact` («[3 элемента]») | `errors.ts` (`kindNames`, форматы) |
| `src/engine/evaluator.ts` | «Заполните вход…», «Нод … выше по графу…», «Неизвестный тип нода…» | `errors.ts` (`stateMessages`) |
| `src/engine/composite.ts` | отказы сворачивания и портов | `errors.ts` (`rejections`) |
| `src/engine/registry.ts`, `builtins/io.ts` | категории «Мои составные ноды», «Интерфейс составного нода», описание по умолчанию | `builtins/define.ts` (`categories`) |
| `src/model/import.ts`, `serialize.ts` | ошибки импорта и чтения файлов | остаются в `importMessages` (модуль модели — источник этих сообщений, как в 001), переводятся |
| `src/store/actions.ts`, `store.ts` | «Нет открытой вкладки», «(копия)», «Новый workflow», «… не найден» | `src/ui/messages.ts` |
| `src/storage/*` | «Файл повреждён…», «Браузер не поддерживает запись файлов»… | остаются в модулях хранилища, переводятся (они не импортируют UI) |
| `src/ui/**` | `aria-label="Хранилище"`, «Входы: …» в подсказке палитры | `src/ui/messages.ts` |

Внутренние ошибки разработчика (`'AppProvider не найден'`) — не тексты для
пользователя, остаются на русском.

**Rationale**: FR-001; движок не может импортировать `src/ui` (`tsconfig.engine.json`),
поэтому тексты движка — в `errors.ts`, а `model` и `storage` держат свои сообщения у
себя, как раньше.

**Alternatives considered**: всё в один `messages.ts` — движок и модель не должны
зависеть от UI (план 001, слои).

## R3. Склонение по числу

**Decision**: русская `plural(n, one, few, many)` заменяется английской
`plural(n, one, other)` в `src/engine/errors.ts`: `1 item`, `3 items`, `0 items`.

**Rationale**: FR-005; в английском две формы.

## R4. Снятие ограничений длины имён

**Decision**: убрать все проверки максимальной длины, оставить «не пусто после trim»:

| Где | Сейчас | Станет |
|---|---|---|
| `src/model/schemas.ts` | `name` нода — `maxLength(100)`; `NameSchema` (workflow, составной нод) — `maxLength(100)`; `PortDefSchema.name` — `maxLength(40)` | только `trim` + `minLength(1)` (для порта — `minLength(1)`, как раньше без trim) |
| `src/engine/validate.ts`, `errors.ts` | `normalizeNodeName`: отказ `name-too-long`, `MAX_NODE_NAME` | отказ и константа удаляются; остаётся `empty-name` |
| `src/engine/composite.ts` | `validateIoPorts`: «от 1 до 40 символов» | только «не пусто» с новым текстом отказа |
| `src/store/actions.ts` | `MAX_NAME = 100` в переименовании workflow и составного нода; `.slice(0, MAX_NAME)` у копии | только «не пусто»; обрезка копии убирается |
| `src/ui/messages.ts` | `invalidName` «от 1 до 100 символов», `copyName(...).slice(0, 100)` | «Name cannot be empty…»; без обрезки |
| `src/ui/layout/WorkflowList.tsx`, `dialogs/NameDialog.tsx`, `canvas/IoPortsEditor.tsx` | `maxLength={100}` / `maxLength={40}` у полей | атрибут убирается |

Формат файлов не меняется (`version: 1`): проверка только ослабляется, старые файлы
ей удовлетворяют (FR-010).

**Rationale**: FR-007 (Clarifications спеки). Длинные имена уже обрезаются многоточием
с полным текстом в подсказке (фича 002, FR-007a и T080/T081); где этого ещё нет —
добавляется (R5).

**Alternatives considered**: оставить мягкий предел (например, 1000) — пользователь
отказался от искусственных ограничений.

## R5. Длинные имена в интерфейсе (FR-008)

**Decision**: проверить и при необходимости добавить многоточие + `title` с полным
текстом там, где имя выводится в одну строку: вкладки (`TabBar`), список workflow
(`WorkflowList`), элементы палитры (`.palette__item-title`), заголовки окон (уже есть,
T081 фичи 002), подписи линий и окно связей (уже есть, T080), строка имени порта в
окне свойств (`.prop-name`, уже есть), заголовок окна свойств (`prop-grid__name`
переносится — оставить). Карточка нода — без изменений (3 строки и многоточие).

**Rationale**: FR-008; снятие ограничений не должно ломать раскладку.

## R6. Совместимость с сохранённой работой

**Decision**: специальных действий нет. Файлы ссылаются на типы по id
(`builtin:add`), имена портов встроенных нодов на латинице; имена пользователя —
данные, не переводятся (FR-010). Тесты: открыть фикстуру рабочей папки и выгрузку,
сохранённые в формате фичи 002 с русскими именами, — вычисляются, имена прежние.

## R7. Страница

**Decision**: `index.html` — `lang="en"`, `<title>DAG Flow</title>` (уже английский).
Документ остаётся UTF-8.

## R8. Тесты

**Decision**:
- Unit и компонентные: ожидаемые тексты переводятся на английский; тексты отказов
  проверяются дословно (принцип IV) по [contracts/ui-texts.md](./contracts/ui-texts.md).
- e2e: локаторы по `aria-label`/`role name` и тексты переводятся. Хелперы
  (`tests/e2e/helpers.ts`, `tests/component/helpers.tsx`) — первыми, чтобы спеки
  переводились механически.
- Названия тестов (`it('…')`, `test('…')`) и комментарии остаются на русском. В
  `playwright.config.ts` фильтр Firefox `grepInvert` опирается на русские названия
  тестов — не меняется.
- Новый e2e US1: обход окон и типовых ошибок без кириллицы (SC-001) — проверка
  `textContent` всего документа на отсутствие кириллицы, без пользовательских данных.
- Новые тесты US2: имя 1000 символов для нода, workflow, составного нода и порта
  (SC-003); имена на разных языках после выгрузки/загрузки (SC-004).
- US3: фикстура в формате 002 с русскими именами.

**Rationale**: принцип II; около 40 файлов тестов меняются только в строках.

## R9. Правило в `CLAUDE.md`

**Decision**: «Интерфейс и все тексты для пользователя — на русском» →
«Интерфейс и все тексты для пользователя — на английском; артефакты Spec Kit,
комментарии и общение — на русском». Подсказка про палитру «Текст» → «Text».
Пометки «уточнено в 003» — у Assumptions 001 и 002 о языке и у ограничений длины
(data-model 001, FR-009 002).
